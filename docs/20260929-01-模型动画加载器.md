## 需求背景

项目当前处于技术验证阶段, 已集成 raylib 6.0(FetchContent 源码构建, 内置 cgltf, 支持 glTF/GLB 加载与骨骼动画 API)。为了验证 raylib 的模型加载与 3D 渲染能力, 并为后续引入角色 / 场景资产做准备, 需要一个基础的模型加载与展示功能。

资产 `assets/models/cartoon_man.glb`(约 26.8 MB)为 Khronos glTF 2.0 二进制格式, 由 Blender 导出:

- 单网格: 32,314 顶点 / 150,000 索引(50,000 三角形)
- 单材质: PBR(baseColor / normal / metallicRoughness 贴图, 使用 `KHR_materials_specular` 扩展;raylib 加载后材质数显示为 2, 因 raylib 会额外追加 1 个默认材质槽)
- **无 skin、无动画数据**(静态模型)

因此动画播放链路(加载 / 播放 / 循环)本次会实现并支持带动画的模型, 但该资产本身只验证静态展示。

## 需求目标

1. 新增 `model/` 模块, 封装 raylib 模型加载: 从指定路径加载模型文件(glTF/GLB 等 raylib 支持的格式), 并在 3D 场景中展示。
2. 支持动画播放链路: 动画选择、播放/暂停、循环、速度调节(对含动画的模型生效)。
3. ImGui 面板可调整相机参数: 位置、目标点、up、FOV、投影方式(透视/正交), 并提供预设视角与「适配模型」。
4. 程序窗口默认尺寸改为 2K(2560×1440, QHD)。
5. ImGui 面板可调整模型变换: 位置、旋转(轴 + 角度)、缩放; 可选线框 / 包围盒显示。
6. 路径解析需兼容不同工作目录(如 IDE 将工作目录设为 `build/` 子目录)。

## 设计方案

### 1. 新增 `core/model/` 模块(第三方库隔离, 与 `log/`、`script/` 同层)

`model_loader.h` / `model_loader.cpp`, `namespace model_loader`, 类 `ModelScene`:

| 接口 | 说明 |
|---|---|
| `bool load(const std::string& path, std::string* error)` | `LoadModel` + `LoadModelAnimations`; 失败返回 false 并记录原因; 内部缓存模型与动画数组 |
| `void unload()` | `UnloadModel` + `UnloadModelAnimations`, 幂等 |
| `void update(float dt)` | 按 60fps 基准推进动画帧: `UpdateModelAnimation`; 处理循环 / 播完停止 |
| `void draw(const Transform&, bool drawWires)` | `DrawModelEx` / `DrawModelWiresEx` |
| `void drawBounds(const Transform&)` | `GetModelBoundingBox` + `DrawBoundingBox`(包围盒不应用旋转, 仅平移) |
| `bool bounds(float center[3], float size[3])` | 供相机「适配模型」计算 |
| `ModelStats stats()` | 网格 / 材质 / 顶点 / 三角形 / 动画数量, 用于 UI 展示与验证 |
| 动画控制 | `animationNames()` / `setActiveAnimation()` / `setPlaying()` / `setLoop()` / `setSpeed()` |

- 模块内部持有 raylib `Model` / `ModelAnimation[]`, **不向应用层暴露 raylib 类型**(遵循 ADR-5 隔离原则)。
- 加载失败判定: `model.meshCount == 0`(raylib 加载失败返回空 Model, 并通过 TraceLog 输出原因)。
- 动画帧率: glTF 导入时 raylib 将时间戳换算为 60fps 帧索引, 播放基准取 60fps。
- `Transform` 为纯数据 struct(位置、旋转轴、旋转角、缩放), 由应用层在 ImGui 中编辑。

### 2. `core/main.cpp` 改造

- 窗口尺寸: `2560 × 1440`(2K), 保持可缩放。
- 主循环绘制: `BeginMode3D(camera)` → `DrawGrid` → `scene.draw(...)`(可选线框 / 包围盒) → `EndMode3D`。
- ImGui 面板「Phoenix」内分三组折叠头:
  - **模型**: 路径输入框 + 加载按钮(默认 `assets/models/cartoon_man.glb`)、统计信息、变换参数、动画控制。
  - **相机**: 位置 / 目标点 / up / FOV / 投影方式; 预设视角按钮(透视默认、前、后、左、右、上)+「适配模型」; 可选鼠标环绕控制(`UpdateCamera(CAMERA_ORBITAL)`, 开启时禁用参数编辑避免冲突)。
  - 保留原有 Lua 验证输出与 ImGui Demo 开关。
- 路径解析 `resolveAssetPath()`: 依次尝试原始路径、逐级 `../` 前缀(最多 4 层)、可执行文件目录, 取第一个存在的文件。
- 模型加载 / 失败通过 `app_log` 记录日志。

### 3. 构建

- `core/CMakeLists.txt` 增加 `model/model_loader.cpp`, 无需新增依赖(raylib 已链接)。
- 无需更新 `vcpkg.json` / 顶层 `CMakeLists.txt`。

  - UI 显示网格数 1、顶点数 32,314、三角形数 50,000、材质数 2(含默认槽)、动画数 0;

## 漏洞修复

### 漏洞 1: ImGui 面板中文显示为问号

- **名称**: ImGui 面板中文文本显示为 `?`
- **背景**: ImGui 默认字体 `ProggyClean` 为位图字体, 仅含 ASCII/Latin 字形, 不含 CJK 字形。`rlImGuiSetup(true)` 内部 `rlImGuiBeginInitImGui()` 仅调用 `io.Fonts->AddFontDefault()`, 未加载任何中文字体, 因此面板中的「模型」「相机」「路径」「加载模型」等中文标签全部渲染为 `?`。
- **修复方案**:
  1. 将 `core/main.cpp` 中的 `rlImGuiSetup(true)` 替换为三步高级初始化, 在字体图集构建前加载 CJK 字体:
     - `rlImGuiBeginInitImGui()`(创建上下文并添加默认字体)
     - `ImGui::StyleColorsDark()`
     - 加载中文字体并以 `MergeMode` 合并进默认字体
     - `rlImGuiEndInitImGui()`(合并 FontAwesome 图标、初始化鼠标光标与后端)
  2. 字体来源: 优先加载 `C:/Windows/Fonts/msyh.ttc`(微软雅黑), 缺失时回退 `C:/Windows/Fonts/simhei.ttf`(黑体); 均不存在则记录 `app_log` warning 并保持默认字体(中文仍显示 `?` 但不崩溃)。
  3. 字表范围: 使用 `io.Fonts->GetGlyphRangesChineseFull()`(全量 CJK, 保证覆盖); 如需降低显存/图集占用可改用 `GetGlyphRangesChineseSimplifiedCommon()`。
  4. 合并字体 `SizePixels` 与默认字体保持一致(13), 避免 ASCII 与中文字形大小错位。
