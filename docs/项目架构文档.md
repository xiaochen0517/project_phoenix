# 项目架构文档

> 版本: v0.7 (2026-10-01, 引入 app/ 应用框架与固定 tick 主循环)
>
> 本文档记录项目的整体架构、技术选型、模块设计与关键架构决策。
> 依据 `AGENTS.md` 约定: 当依赖库、项目架构或其他相关内容发生变化时, 必须同步更新本文档。

## 1. 项目概述

- 项目名称: project_phoenix
- 项目定位: 基于 [raylib](https://www.raylib.com/) 的 C++17 桌面程序, 集成 spdlog 日志与 LuaJIT + sol2 脚本绑定
- 当前阶段: 技术验证阶段。`core/main.cpp` 目前是验证「窗口 + 渲染 + ImGui + 模型加载 + 日志 + LuaJIT + sol2 脚本绑定」集成的示例程序, 尚无业务功能

## 2. 技术栈与依赖

| 库 | 版本 | 来源 | 用途 |
|---|---|---|---|
| C++ | C++17 | 编译器 | 开发语言 |
| raylib | 6.0 | CMake `FetchContent` 源码构建 | 窗口与图形渲染 (内置 cgltf, 支持 glTF/GLB 模型加载与骨骼动画) |
| Dear ImGui | 1.92.7 | CMake `FetchContent` 源码构建 | 即时模式 GUI |
| rlImGui | `Raylib_6_0` tag 对应提交 `3bc5731` | CMake `FetchContent` 源码构建 | raylib 的 ImGui 后端桥接 |
| spdlog | 由 baseline 固定 | vcpkg (manifest 模式) | 日志 |
| LuaJIT | 官方 2.1 线 (baseline 固定 2026-09-08 提交 `c6ffc141`) | vcpkg (manifest 模式) | 脚本 (Lua 5.1 API + JIT) |
| sol2 | 3.5.0 | vcpkg (manifest 模式) | C++ ↔ Lua 绑定 (header-only) |
| Catch2 | 由 baseline 固定 | vcpkg (manifest 模式) | 单元测试框架 |

构建工具链: CMake >= 3.21 + Ninja; Windows 使用 MSVC, Linux 使用 GCC 或 Clang。

## 3. 总体架构

当前为**单体可执行文件**结构, 由 `core` 单一目标构成。逻辑上分两层:

```text
┌─────────────────────────────────────┐
│  应用层: app/ (App + Game)           │  窗口 / 主循环 / 固定 tick + 业务载体
│  └── main.cpp (入口, 组装 App)       │
├─────────────────────────────────────┤
│  基础设施层                          │
│  ├── log/    (spdlog 封装)           │  第三方库不直接暴露给应用层
│  ├── script/ (LuaJIT 持久引擎, sol2)  │
│  ├── model/  (raylib 模型封装)       │
│  └── util/   (asset_path 等工具)     │
└─────────────────────────────────────┘
```

核心设计原则:

- **第三方库隔离封装**: 每个第三方库通过独立模块封装后再被应用层使用, 避免第三方头文件互相冲突(见 §6)。
- **依赖版本全固定**: 源码依赖通过 `URL + SHA256` 固定, vcpkg 依赖通过 `builtin-baseline` 固定, 保证构建可复现。
- **Windows 仅支持 MSVC**: 受 vcpkg triplet 与 ABI 约束(见 §7)。

## 5. 构建系统

### 5.1 CMake 层次

- **顶层 `CMakeLists.txt`**: 只负责依赖获取与全局约束, 不直接编译业务代码
  - `find_package(spdlog / sol2 / Catch2)` 从 vcpkg 获取; LuaJIT 经 `find_path / find_library` 定位 (luajit port 仅导出 pkgconfig, 无 CMake config)
  - `enable_testing()` 启用 ctest 调度
  - `FetchContent` 获取 raylib 6.0、Dear ImGui 1.92.7、rlImGui 源码
  - ImGui 与 rlImGui 均不提供官方 CMake 配置, 由顶层手动编入静态库 `rlimgui`
  - 强制关闭 raylib 的 `BUILD_EXAMPLES` / `BUILD_SHARED_LIBS` / `USE_EXTERNAL_GLFW`
- **`core/CMakeLists.txt`**: 定义可执行目标 `project_phoenix`, 链接 `raylib rlimgui spdlog::spdlog ${LUAJIT_LIBRARY} sol2::sol2`; 另定义测试目标 `project_phoenix_tests` (复用 `log/` 与 `script/` 源文件, 链接 `Catch2::Catch2WithMain`, 不链接 raylib/model_loader), 经 `add_test` 接入 ctest

### 5.2 vcpkg (manifest 模式)

- 依赖清单与版本基线集中在 `vcpkg.json` (`builtin-baseline` 固定)
- preset 通过 `VCPKG_ROOT` 环境变量接入 vcpkg toolchain
- Windows triplet: `x64-windows-static-md` (静态库 + 动态 CRT)

### 5.3 构建 Preset

| Preset | 平台 | 说明 |
|---|---|---|
| `msvc-debug` / `msvc-release` | Windows | Ninja + cl (MSVC) |
| `linux-debug` / `linux-release` | Linux | Ninja + GCC/Clang |

同名 `testPresets` 与 configure/build preset 一一对应, 供 `ctest --preset <name>` 直接运行单元测试。

## 6. 模块设计

### 6.1 `log/` — 日志封装

- `namespace app_log`, 对 spdlog 做薄封装: `init()` / `debug()` / `info()` / `warn()` / `error()` / `critical()`
- `init()` 统一设置日志 pattern (`[%H:%M:%S.%e] [%^%l%$] %v`) 与级别 (debug)
- **设计动机**: spdlog 在 Windows 上会引入 `<windows.h>`, 与 `raylib.h` 在同一源文件中存在宏冲突; 独立成模块后, 应用层只 include `app_log.h`, 隔离冲突

### 6.2 `script/` — LuaJIT 持久脚本引擎 (sol2 封装)

- `namespace lua_engine`, 类 `Engine` — 基于 sol2 的持久脚本引擎:
  - 构造时创建 `sol::state` 并 `open_libraries()` (无参, 确保 `jit` 注册为全局变量)
  - `bool do_file(const std::string& path)`: 加载并执行一个 `.lua` 文件; 出错经 `app_log::error` 输出并返回 `false`
  - `bool reload(const std::string& path)`: 重新执行已加载文件 (手动基础重载, 覆盖全局量; 函数级/自动监听热重载留到 P7)
  - `Value call_function(const std::string& name)`: 调用全局函数并返回基础类型值 (nil / bool / number / string); P0 仅无参, 参数与对象绑定在 P0-04 扩展
- `class Value` — 基础类型值包装 (`std::variant<monostate, bool, double, string>`), 隔离 sol2 类型, 应用层不直接接触 `sol::object` (ADR-5)
- `sol::state` 以 pimpl 形式持有在 `lua_engine.cpp`, sol2 头文件不向应用层暴露 (ADR-5)
- 路径解析: `do_file` 接收显式路径, 运行时复用 `asset_path::resolve` 定位 `lua/` 脚本; 单元测试经 CMake compile definition `PROJECT_PHOENIX_LUA_DIR` 注入 `lua/` 绝对路径 (无头可跑)
- `namespace api` — API 绑定框架 (`api_registry`): 建立 `api.<module>.<func>` 注册约定, 每个业务模块提供 `register_<module>(lua_State*)`, 由 `register_all(Engine&)` 统一汇总挂到 `api` 表。`Engine::raw_state()` 暴露内部 `sol::state` 的裸 `lua_State*` 供绑定层使用, sol2 头仅出现在 `api_registry.cpp` (ADR-5)。P0-04 绑定 `api.log.*` (→ `app_log`) 与 `api.util.add` (返回值链路演示)

### 6.3 `model/` — 模型加载与动画封装

- `namespace model_loader`, 类 `ModelScene`, 对 raylib 模型 API 做薄封装:
  - `load(path, &error)`: `LoadModel` + `LoadModelAnimations`(glTF/GLB 等), 失败判定 `meshCount == 0`; 内部缓存模型与动画数组
  - `update(dt)`: 动画推进 (60fps 基准, `UpdateModelAnimation`), 支持选择 / 播放暂停 / 循环 / 速度
  - `draw(transform, drawWires)` / `drawBounds(transform)`: `DrawModelEx` / `DrawModelWiresEx` / `GetModelBoundingBox` + `DrawBoundingBox`
  - `bounds()` / `stats()`: 包围盒与网格统计, 供相机适配与 UI 展示
  - `applyTexture(mapType, path)`: 动态加载贴图并绑定到模型所有材质的指定贴图槽 (`MaterialMapType` 枚举对应 raylib `MaterialMapIndex`, 支持基础色 / 法线 / 遮罩等), 供应用层运行时换贴图
- **设计动机**: 与 `log/`、`script/` 一致, raylib 类型不向应用层暴露 (ADR-5); 应用层通过纯数据 struct `Transform` 控制模型变换

### 6.4 `app/` — 应用框架层

`main.cpp` 瘦身为纯入口: `app_log::init()` → 创建 `app::App(std::make_unique<ModelViewerGame>())` → `app.run()`。

- `app::Game` — 业务载体抽象接口: `init()` / `update(fixedDt)` / `render(alpha)` / `shutdown()`, 供后续真实游戏场景替换 (ADR-10)。
- `app::App` — 应用外壳: 负责 `InitWindow` / `SetTargetFPS(60)` / CJK 字体 / `rlImGuiSetup` / 主循环 / `rlImGuiShutdown` / `CloseWindow` 等框架级职责, 不依赖具体业务。
- `app::ModelViewerGame` — P0 阶段的运行载体, 迁移自原 `main.cpp` 的模型查看器, 语义不变。

初始化顺序: `app_log::init()`(main) → `InitWindow`(默认 2560×1440, 2K) → CJK 字体 → `game.init()`(默认模型加载) → 主循环 → `game.shutdown()` → `rlImGuiShutdown` / `CloseWindow`。

模型查看器主循环内 (迁移至 `ModelViewerGame`):
- ImGui 面板分「模型」「相机」折叠组: 模型路径加载、变换参数、动画控制; 相机位置 / 目标 / up / FOV / 投影 / 预设视角 / 适配模型 / 鼠标环绕控制 / 手动飞行控制
- 相机控制支持两种互斥模式:
  - **环绕控制**: `UpdateCamera(CAMERA_ORBITAL)`, 鼠标绕目标点旋转 + 滚轮缩放
  - **手动飞行**: 匿名命名空间辅助函数 `updateManualCamera`, 编辑器风格 `W/A/S/D` 前后左右(以视角朝向为准, 含垂直分量) + `空格/Ctrl` 升降 + 按住右键捕获鼠标旋转视角; 复用 raylib `rcamera.h` 的 `CameraMoveForward/MoveRight/MoveUp/Yaw/Pitch` 原语(`model_viewer_game.cpp` 需额外 `#include "rcamera.h"`, 因 `raylib.h` 仅暴露 `UpdateCamera/UpdateCameraPro`); 移动速度 / 旋转速度可在 ImGui 中配置, 右键旋转时经 `DisableCursor` 捕获鼠标, 期间置位 `ImGuiConfigFlags_NoMouseCursorChange` 以避免与 rlImGui 的每帧光标管理冲突

### 6.5 `app/` — 固定 tick 主循环

采用「Fix Your Timestep」累加器模式: `FIXED_DT = 1/30`, 帧时间累加到 `accumulator` 后, 每次扣减 `FIXED_DT` 调用一次 `game_->update(FIXED_DT)` (可能一次或多次追帧); `render(alpha)` 每帧调用一次, `alpha = accumulator / FIXED_DT` (∈ [0,1)) 供渲染插值。帧时间上限 `0.25s` 防止卡顿后累加器死亡螺旋。每秒经 `app_log` 输出一次 tick 计数, 用于人工核对逻辑以 30Hz 推进。

### 6.6 `util/` — 通用工具

- `namespace asset_path` — `resolve(requested)`: 依次尝试原始路径、逐级 `../` 前缀(最多 4 层)、可执行文件目录, 兼容不同工作目录 (如 IDE 将工作目录设为 `build/` 子目录); 未找到返回原始路径交由加载器报错。抽自原 `main.cpp` 的 `resolveAssetPath`, 供后续 `config/` 等复用。

## 7. 关键架构决策

| 编号 | 决策 | 原因 |
|---|---|---|
| ADR-1 | raylib 不通过 vcpkg 获取, 改用 `FetchContent` 源码构建并复用其自带 GLFW | vcpkg 的 raylib 使用外部 glfw3 (`USE_EXTERNAL_GLFW=ON`), 在本项目环境下出现首帧后 swap 忙等、窗口无响应的问题 |
| ADR-2 | ImGui / rlImGui 同样走 `FetchContent`, 固定配套版本 (raylib 6.0 + ImGui 1.92.7 + `Raylib_6_0` tag) | 三者无官方 CMake 集成, 自行构建静态库可精确控制版本配套关系 |
| ADR-3 | Windows triplet 使用 `x64-windows-static-md` 并仅支持 MSVC | vcpkg 在 `project()` 内决定 triplet, 无法自动匹配 MinGW; 预设 triplet 为 MSVC ABI |
| ADR-4 | 所有第三方依赖版本固定 (URL + SHA256 / builtin-baseline) | 保证构建可复现, 避免漂移 |
| ADR-5 | 第三方库按目录封装 (`log/`, `script/`, `model/`) | 隔离头文件冲突, 应用层不直接依赖第三方头文件 |
| ADR-6 | 资源路径用 `resolveAssetPath()` 多级回退解析, 不硬编码工作目录 | IDE 与命令行启动的工作目录不同, 相对路径直接使用不可靠 |
| ADR-7 | 脚本引擎由 PUC Lua (5.4) 切换为官方 LuaJIT (Lua 5.1 + JIT) | 为游戏脚本的高频逻辑 / 热更新提供 JIT 加速与 FFI; LuaJIT API 兼容 Lua 5.1 |
| ADR-8 | C++ 绑定采用 sol2 (header-only), 封装在 `script/lua_engine` | 最主流、生态最大的 C++ Lua 绑定库, 对 LuaJIT 一等支持; 按 ADR-5 隔离 sol2 头文件, 应用层不直接依赖 |
| ADR-9 | 单元测试采用 Catch2, 通过独立测试目标 `project_phoenix_tests` 无头运行 | 纯逻辑层可自动回归; 测试目标不链接 raylib/model_loader (需 GL 上下文与资产), 保证命令行 / CI 可直接运行 |
| ADR-10 | 应用框架采用「App + Game + 固定 tick」结构, 拆分 `main.cpp` | 分离框架外壳与业务载体; 逻辑以固定 30Hz 步长推进、渲染按帧插值, 为后续 ECS / 事件 / 脚本逻辑提供稳定更新基准 |
| ADR-11 | 脚本引擎由一次性求值演进为持久 `sol::state` (`script/lua_engine`), 支持模块加载与基础重载 | 承载跨帧游戏脚本逻辑; 收敛 `lua_runner`(原生 C API 一次性) 与 `sol2_bridge`(自检) 为单一持久引擎, sol2 头经 pimpl 隔离 (ADR-5) |
| ADR-12 | API 绑定框架 (`api.*` 注册约定): 各模块 `register_<module>(lua_State*)` + `register_all` 汇总 | 打通 C++→Lua 调用链, 统一挂 `api.<module>.<func>` 命名空间; 绑定层经裸 `lua_State*` + `sol::state_view`, sol2 头仅出现在 `.cpp` (ADR-5) |

## 8. 已知问题与限制

- 尚无 CI 流程 (单元测试已接入 Catch2, 需本地 `ctest` 运行)
- Windows 不支持 MinGW 工具链
- 模型加载为同步阻塞 (`LoadModel`), 26MB 的 GLB 加载约 2~3 秒; 换模型时 UI 会卡顿, 后续需异步加载
- 包围盒绘制仅应用平移不应用旋转; 相机「适配模型」基于未变换的本地包围盒
