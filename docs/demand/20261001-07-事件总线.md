## 需求背景

P0-04 已落地 `api.*` 绑定框架，打通了 **C++ → Lua** 的调用链（Lua 可调 `api.log.*`、`api.util.add`）。但这条链是单向的：Lua 能「调用 API」，却还**收不到 C++ 侧的主动推送**，C++ 侧也**不知道 Lua 侧发生了什么**。

P0 总验收标准要求「Lua 能读配置、调用 API、**收发事件**」。其中「收发事件」需要一个**事件总线**：C++ 与 Lua 双方都能「产生事件」和「订阅事件」，通过一个共享的中介完成**双向**解耦通信。当前缺失这一层，需要实现一个支持 C++ / Lua 双端订阅与分发的事件总线。

## 需求目标

1. 实现纯 C++ 事件总线 `event::Bus`：事件名 + 载荷值，支持 `on`（订阅）/ `off`（取消订阅）/ `emit`（同步分发）。
2. 绑定 `api.event.*` 到 Lua：`api.event.on(name, func)` 注册 Lua 处理函数、`api.event.emit(name, payload)` 从 Lua 产生事件。
3. 打通双向链路：C++ `emit` → Lua handler 被调用；Lua `emit` → C++ 订阅者收到。
4. 事件载荷用基础类型（nil / bool / number / string），经绑定层转换，sol2 头继续隔离在 `.cpp`（ADR-5）。
5. 单元测试覆盖两条双向验收链。

## 设计方案

### 1. 事件总线核心（`event/`，纯 C++，不依赖 sol2）

新增 `core/event/event_bus.{h,cpp}`，`namespace event`，与 `script/` 解耦（依赖方向为 `script` → `event`，`event` 是更底层的基础设施，不反向依赖 sol2 / lua_engine）。

#### 1.1 `event::Value` — 载荷值

对齐 `lua_engine::Value` 的语义，用 `std::variant<std::monostate, bool, double, std::string>` 收敛四类基础类型：

```cpp
class Value {
public:
    Value();                                   // nil
    static Value nil();
    static Value boolean(bool v);
    static Value number(double v);
    static Value string(std::string v);

    bool is_nil() const;
    bool is_bool() const;        bool as_bool() const;
    bool is_number() const;      double as_number() const;
    bool is_string() const;      std::string as_string() const;
private:
    std::variant<std::monostate, bool, double, std::string> data_;
};
```

选择四类基础类型，与 sol2 的类型转换天然对齐（`number`→`double`、`string`→`std::string`、`bool`→`bool`、`nil`→`monostate`），无需引入 usertype 对象绑定，符合 P0 最小闭环。

#### 1.2 `event::Bus` — 订阅表 + 同步分发

```cpp
class Bus {
public:
    using Handler = std::function<void(const Value &)>;
    using SubscriptionId = std::uint64_t;

    SubscriptionId on(const std::string &name, Handler handler);
    void off(const std::string &name, SubscriptionId id);
    void emit(const std::string &name, const Value &payload = Value::nil());
private:
    // 订阅表: 事件名 -> [(订阅 id, handler), ...]
    std::unordered_map<std::string, std::vector<Entry>> subscribers_;
    std::uint64_t next_id_ = 0;
};
```

要点：

- **同步分发**：`emit` 遍历该事件的订阅列表逐个调用（roadmap 已定同步分发，延迟队列后续按需引入）。
- **订阅表结构**：`unordered_map<string, vector<Entry>>`，`Entry = {SubscriptionId, Handler}`；订阅 id 单调递增，供 `off` 精确移除。
- **`on` 语义**：同名事件可重复订阅，`emit` 时每个订阅各触发一次；P0 阶段不限制重复，`off` 提供基础移除能力（验收不强制覆盖）。
- 载荷默认 `Value::nil()`，允许无载荷事件。

### 2. 绑定 `api.event.*`（`script/api_registry`）

`register_event` 负责把 `event::Bus` 绑定到 Lua。由于事件总线是**有状态对象**（订阅表），与无状态的 `api.log` 不同，`register_event` 需要引用外部 `event::Bus` 实例：

```cpp
// api_registry.h 增补
namespace event { class Bus; }  // 前置声明 (ADR-5, 不 include 任何第三方头)

namespace api {
    void register_all(lua_engine::Engine &engine);                    // 既有, 不变
    void register_event(lua_State *L, event::Bus &bus);               // 新增: 事件总线绑定
}
```

`api_registry.cpp` 实现要点（sol2 头仅在此处）：

```cpp
void register_event(lua_State *L, event::Bus &bus) {
    sol::state_view lua(L);
    sol::table api = lua["api"].get_or_create<sol::table>();
    sol::table ev = api["event"].get_or_create<sol::table>();

    // Lua 注册的 handler 存这里 (sol2 类型仅在本 .cpp, shared_ptr 保持引用防 GC)。
    struct LuaHandler {
        std::shared_ptr<sol::protected_function> func;
        event::Bus::SubscriptionId id;
    };
    auto handlers =
        std::make_shared<std::unordered_map<std::string, std::vector<LuaHandler>>>();

    // api.event.on(name, func): 追加一个 Lua handler, 并向 bus 订阅桥接 lambda。
    ev["on"] = [handlers, &bus](std::string name, sol::protected_function func) {
        auto h = std::make_shared<sol::protected_function>(func);
        auto id = bus.on(name, [h](const event::Value &payload) {
            // 载荷经 sol::state_view 转成 sol 对象传给 Lua 函数。
            sol::state_view lv(h->lua_state());
            auto result = (*h)(to_sol_object(lv, payload));
            if (!result.valid()) {
                sol::error err = result;   // 经 app_log 输出, 不静默吞掉
                app_log::error(std::string("api.event handler error: ") + err.what());
            }
        });
        (*handlers)[name].push_back(LuaHandler{h, id});
    };

    // api.event.off(name): 移除该事件名下所有 Lua 注册的 handler (含对应 bus 订阅)。
    ev["off"] = [handlers, &bus](std::string name) {
        auto it = handlers->find(name);
        if (it == handlers->end()) {
            return;
        }
        for (auto &entry : it->second) {
            bus.off(name, entry.id);
        }
        handlers->erase(it);
    };

    // api.event.emit(name, payload?): Lua 侧产生事件, 转 event::Value 后同步分发。
    ev["emit"] = [&bus](std::string name, sol::object payload) {
        bus.emit(name, to_event_value(payload));
    };
}
```

绑定层内部辅助函数（`api_registry.cpp` 匿名命名空间）：

- `to_sol_object(sol::state_view &, const event::Value &)`：`event::Value` → `sol::object`（number/string/bool/nil）。
- `to_event_value(const sol::object &)`：`sol::object` → `event::Value`（按 `is<double>`/`is<std::string>`/`is<bool>`/`is<sol::nil_t>` 判定）。

要点：

- Lua handler 用 `std::shared_ptr<sol::protected_function>` 存储（保持 registry 引用，防 GC）；存储容器为 `std::shared_ptr`，被 `on`/`off`/`emit` 的 lambda 共享捕获，生命周期随绑定层存活。
- **同名多 handler**：`api.event.on` 同名事件每次追加一个 handler 到 `vector`，并各自向 `bus` 订阅一个桥接 lambda，`emit` 时每个 handler 各触发一次。
- 桥接 lambda 按值捕获自己的 handler 指针（`std::shared_ptr`），`off` 移除后不会悬空（lambda 仍持有引用，只是对应 bus 订阅已移除、不再被触发）。
- 桥接 lambda 调用 Lua 函数时用 `sol::protected_function` 的受保护调用，出错经 `app_log::error` 输出，不崩溃、不静默吞掉（沿用 P0-03/04 约定）。
- `api.event.off(name)` 按事件名移除该事件下全部 Lua handler；精确按 id 移除由 C++ `Bus::off(name, id)` 提供（Lua 侧不暴露 id）。

### 4. 单元测试（`tests/test_event_bus.cpp`）

| 用例 | 验证点 |
|---|---|
| C++ `emit` → Lua handler 被调用 | 注册 `api.event.*`，`do_file` 加载脚本（`api.event.on("evt", function(p) called = true end)` + `function was_called() return called end`）→ C++ `bus.emit("evt", ...)` → `call_function("was_called")` 返回 `true` |
| Lua 同名多 handler 都被调用 | 脚本对同一事件 `on` 两个 handler，各累加计数器 → C++ `emit` → 断言两个 handler 都被触发（计数正确） |
| Lua `emit` → C++ 订阅者收到 | C++ `bus.on("lua_evt", handler)`（handler 置 `received = true` 并校验载荷）→ `do_file` 加载脚本 `api.event.emit("lua_evt", 123)` → 断言 `received == true` 且载荷为 `123.0` |
| `api.event.off` 移除后不再触发 | Lua 注册 handler → 脚本内调 `api.event.off("evt")` → C++ 再 `emit` → `was_called()` 仍返回 `false`（handler 不再被调用） |
| 纯 C++ 同步分发 | 不依赖 Lua：C++ `on` 多个订阅者 → `emit` → 全部被调用，且按订阅顺序同步执行（补一条核心逻辑回归） |

- 载荷校验：第三条用例验证 `event::Value` 载荷从 Lua `123`（number）正确转成 `double` 后回传 C++。
- 脚本路径沿用 `PROJECT_PHOENIX_LUA_DIR` 拼接绝对路径（P0-03 已建立），无需动态写入临时脚本。

## 确认结果 (2026-10-01)

1. **事件载荷类型范围**：P0 仅支持四类基础类型（nil / bool / number / string），不做任意 usertype / 表对象绑定。
2. **`register_event` 签名**：采用注入方案 `register_event(lua_State *, event::Bus &)`；`register_all(Engine&)` 保持不动，event 由调用方显式注册（P0-09 应用层创建 bus 后注册）。
3. **同名重复订阅语义**：`api.event.on` 同名事件支持**多 handler 列表**，`emit` 时每个 handler 各触发一次。
4. **`off` 范围**：同时暴露 `api.event.off(name)` 到 Lua（按事件名移除该事件下全部 Lua handler）；C++ 侧 `Bus::off(name, id)` 提供精确按 id 移除。
