> 状态: 已完成 (2026-10-01)
>
> 日期: 2026-10-01

> 关联: `docs/roadmap/P0骨架需求拆分.md`(P0-06)、`docs/项目架构文档.md`(§6.6 util、ADR-5/ADR-6)

## 需求背景

P0-05 已落地事件总线，P0-03/04 已落地 Lua 引擎与 `api.*` 绑定框架。但到当前为止，程序还没有一个统一的**配置读取层**：所有参数都硬编码在代码或脚本里，无法从外部 JSON 文件加载。

P0 总验收标准要求「Lua 能**读配置**、调用 API、收发事件」。其中「读配置」依赖一个 **JSON 配置系统**：把 JSON 文件加载进内存，提供类型安全的读取接口（按 key 读取、带默认值读取、嵌套访问）与基础校验（必填/可选字段）。当前缺失这一层，需要实现 `config/` 模块。

## 需求目标

1. 引入 `nlohmann/json`（header-only，vcpkg 可用，选型见 roadmap §1），实现 JSON 文件加载与错误报告。
2. 实现类型安全读取接口：按 key 读取、带默认值读取、点分隔路径嵌套访问。
3. 实现基础校验：必填字段 + 可选字段。
4. 遵守 ADR-5：`nlohmann/json` 头文件隔离在 `.cpp`，公开头不暴露第三方类型。
5. 单元测试覆盖验收链（加载、读取、默认值、非法 JSON、校验）。

## 设计方案

### 1. 依赖引入

- `vcpkg.json`：新增 `nlohmann-json`（package 名 `nlohmann-json`）。
- 顶层 `CMakeLists.txt`：`find_package(nlohmann_json CONFIG REQUIRED)`，提供 target `nlohmann_json::nlohmann_json`（header-only）。

### 2. `config/` 模块（纯逻辑，pimpl 隔离第三方头）

新增 `core/config/config.{h,cpp}`，`namespace config`，只依赖标准库 + nlohmann/json，**不依赖 raylib / asset_path / sol2 / lua_engine**（config 是更底层的基础设施，依赖方向为其它模块 → config，不反向）。

```cpp
// core/config/config.h
#pragma once

#include <cstdint>
#include <memory>
#include <optional>
#include <string>
#include <vector>

namespace config {
// 配置文档: 包装一份已解析的 JSON 对象, 提供类型安全读取与校验。
// 采用 pimpl 隔离 nlohmann/json 头文件 (ADR-5), 公开头不暴露第三方类型。
class Document {
public:
    Document(); // 空文档 (无字段)
    ~Document();

    Document(Document&&) noexcept;
    Document& operator=(Document&&) noexcept;
    Document(const Document&) = delete;
    Document& operator=(const Document&) = delete;

    // 按点分隔路径读取 (如 "window.width"), 字段不存在或类型不匹配时返回默认值。
    bool get_bool(const std::string& path, bool def) const;
    std::int64_t get_int(const std::string& path, std::int64_t def) const;
    double get_double(const std::string& path, double def) const;
    std::string get_string(const std::string& path, std::string def) const;

    // 校验: 必填字段 + 可选字段; 返回缺失的必填字段与未声明的未知字段。
    struct ValidationResult {
        std::vector<std::string> missing; // 必填但缺失
        std::vector<std::string> unknown; // 存在但未在 required/optional 声明
        bool ok() const { return missing.empty() && unknown.empty(); }
    };
    ValidationResult validate(const std::vector<std::string>& required,
                              const std::vector<std::string>& optional = {}) const;

private:
    struct Impl;
    std::unique_ptr<Impl> impl_;
    friend std::optional<Document> load_file(const std::string& path);
};

// 从文件加载 JSON 文档; 文件不存在或解析失败时返回 std::nullopt (经 app_log::error 输出)。
std::optional<Document> load_file(const std::string& path);
} // namespace config
```

要点：

- **pimpl 隔离**：`Impl` 持有 `nlohmann::json`（header-only，若暴露在公开头会拖慢所有包含 `config.h` 的编译单元），与 `lua_engine` 隔离 sol2 的动机一致（ADR-5）。
- **点分隔路径嵌套访问**：`get_*("window.title", ...)` 按 `.` 拆段逐级向下查找，支持多层嵌套；key 本身含 `.` 的情况 P0 阶段不考虑（约定配置文件 key 不含点）。
- **类型严格匹配**：`get_int` 仅接受 JSON 整数（`is_number_integer`），`get_double` 接受整数或浮点（`is_number`），`get_bool`/`get_string` 分别匹配 bool/string；不匹配时按「缺失」处理（返回默认值），与 nlohmann 默认的 type 检查一致。
- **接口仅保留默认值版本**：实现时发现 `get_*(path, T& out)`（返回 bool）与 `get_*(path, T def)`（返回 T）两个重载对左值实参存在**重载歧义**（C2668），故去掉 out 版本，只保留默认值版本；「字段是否存在」的需求由 `validate` 覆盖（见 §3）。此调整记录于文末「验证结果」。
- **`load_file` 失败语义**：文件不存在或 JSON 语法错误时经 `app_log::error` 输出具体原因（含文件路径），返回 `std::nullopt`，不抛异常、不崩溃（沿用 P0-03/04「不静默吞掉」约定）。因项目未启用 `/EHsc`（编译命令无该 flag，C4530 警告提示），解析用 nlohmann 非异常 `parse(stream, nullptr, false)` + `is_discarded()` 判断失败，避免依赖 `try/catch` 捕获 `parse_error`。

### 3. 基础校验语义

`validate(required, optional)` 仅校验**顶层字段**（P0 最小范围，嵌套校验留后续）：

- `required`：必填顶层 key 列表，缺失的收集进 `missing`。
- `optional`：可选顶层 key 列表，存在即合法。
- 文档中任何既不在 `required` 也不在 `optional` 的顶层 key，收集进 `unknown`。
- `optional` 缺省为空，即「所有字段要么必填、要么算未知」。

### 4. 路径解析职责（关键设计决策）

`asset_path::resolve`（`core/util/asset_path.cpp`）当前依赖 raylib 的 `FileExists` / `GetApplicationDirectory`，而单元测试目标 `project_phoenix_tests` 无头运行、**不链接 raylib**（见 `core/CMakeLists.txt`）。若 `config` 内部直接调用 `asset_path::resolve`，会迫使测试目标链接 raylib，破坏「纯逻辑可无头自动回归」的既有原则（ADR-9）。

因此 P0-06 采用**职责分离**：

- `config::load_file(path)` 接受**已经可用的文件系统路径**，不做工作目录回退解析。
- 路径解析（`asset_path::resolve`）由**调用方**负责：运行时在 `app/` 层先 `resolve` 再传入 `load_file`（P0-09 集成时落地）。
- 单元测试直接用绝对路径加载测试 JSON，经 compile definition `PROJECT_PHOENIX_CONFIG_DIR` 注入（与既有 `PROJECT_PHOENIX_LUA_DIR` 同构）。

这样 `config/` 保持纯逻辑、可无头测试，同时 `asset_path` 仍按 §6.6 的设计「供 config 的运行时集成复用」（复用在 app 层，而非 config 模块内部）。

> 这是 roadmap §3 P0-06 第 4 条「路径解析复用 `util/asset_path`」与 ADR-9「测试目标不链接 raylib」之间的冲突点，方案见文末「确认点」1。

### 6. 单元测试（`tests/test_config.cpp`）

测试 JSON 路径经 `PROJECT_PHOENIX_CONFIG_DIR` 拼绝对路径（与 `PROJECT_PHOENIX_LUA_DIR` 同构）。

| 用例 | 验证点 |
|---|---|
| 加载合法 JSON 并读取基础字段 | `load_file("config/test_basic.json")` 成功；`get_string("title")`/`get_int("width")`/`get_double("scale")`/`get_bool("fullscreen")` 返回正确值 |
| 嵌套访问（点分隔路径） | `get_string("window.title")`、`get_int("window.width")` 取到嵌套字段值 |
| 带默认值读取 | 缺失字段 `get_int("missing", 42)` 返回 `42`；类型不匹配 `get_int("title", 42)` 返回 `42`（不崩溃） |
| 非法 JSON 报错不崩溃 | `load_file("config/test_invalid.json")` 返回 `std::nullopt`，`app_log::error` 有输出，不抛异常 |
| 必填/可选校验 | `validate({"title","width"}, {"height"})`：`missing` 为空、`unknown` 含 `fullscreen`/`scale`/`window`；`validate({"title","nonexistent"})`：`missing` 含 `nonexistent` |

## 确认结果 (2026-10-01)

1. **路径解析职责**：接受「config 保持纯逻辑、不依赖 `asset_path`/raylib」的职责分离方案。`config::load_file(path)` 接受已可用路径；路径解析由调用方（app 层，P0-09 集成时）用 `asset_path::resolve` 完成；单元测试用 `PROJECT_PHOENIX_CONFIG_DIR` 注入绝对路径加载。
2. **接口形态**：接受 pimpl 隔离 `nlohmann/json` + `config::Document`（`get_*` 读取 + `validate` 校验）+ `config::load_file` 返回 `std::optional<Document>` 的形态。
3. **嵌套访问语法**：接受点分隔路径（`"window.title"`）作为嵌套访问约定。
4. **校验语义**：接受 `validate(required, optional)` 仅校验顶层字段（`missing` 必填缺失 + `unknown` 未声明），嵌套校验留后续。
5. **测试资产目录**：接受在项目根目录新建 `config/`（与 `lua/` 并列）存放测试 JSON。

### 实现偏离说明

1. **接口简化为仅默认值版本**：原设计的 `get_*(path, T& out)` 与 `get_*(path, T def)` 两个重载对左值实参产生 C2668 重载歧义，故去掉 out 版本，只保留默认值版本（`validate` 已覆盖字段存在性判断）。
2. **解析改为非异常 API**：项目编译未启用 `/EHsc`（C4530 警告提示异常展开未启用），原 `try/catch` 捕获 `parse_error` 不可靠，改用 nlohmann 3.12 非异常 `parse(stream, nullptr, false)` + `is_discarded()` 判断失败。
3. **补齐 `.clang-format`**：`AGENTS.md` 要求 `PointerAlignment: Left`，但原 `.clang-format` 缺少该行（默认 Microsoft 的 Right 对齐），已补上并与现有代码（`event_bus.h` 等 Left 风格）保持一致。
