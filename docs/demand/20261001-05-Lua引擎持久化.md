## 需求背景

当前 `script/` 下的脚本能力是**一次性执行模型**，无法承载跨帧的游戏脚本逻辑：

- `lua_runner::eval_string`：每次调用 `luaL_newstate()` → `luaL_openlibs()` → `luaL_dostring()` → `lua_close()`，无状态跨调用保留（见架构文档 §8 已知问题）。
- `sol2_bridge::self_test`：仅用于验证 sol2 + LuaJIT 绑定的功能自检（需求 `20261001-01/02` 落地），纯测试用途，无业务价值。

P0 骨架要求「Lua 能读配置、调用 API、收发事件」，这些能力都依赖一个**有生命周期的、持久的 Lua 引擎**，能加载模块并在运行期重载。因此需要把脚本层从「一次性求值 + 自检」重构为「持久 `lua_State` + 模块加载 + 基础重载」。

## 需求目标

1. 用 sol2 封装持久的 `sol::state`，替换现有一次性 `eval_string`，支持 `do_file` / `call_function` / `reload`（手动触发基础重载）。
2. 清理旧的一次性 Lua 相关测试代码（`lua_runner`、`sol2_bridge` 及对应测试、运行期启动自检）。
3. 新增项目根目录 `lua/` 文件夹，所有 `.lua` 脚本（含临时测试脚本）统一存放于此。
4. 错误经 `app_log` 输出，不静默吞掉。

## 设计方案

### 1. sol2 绑定库分析结论（涉及）

**涉及**。P0-03 的核心即「用 sol2 封装持久 `lua_State`」——用 sol2 的 `sol::state`（对 `lua_State*` 的 RAII 封装）替代 `lua_runner` 中的原生 Lua C API 一次性模型。具体结论：

- **现状**：`lua_runner` 用原生 C API（`luaL_newstate` / `luaL_dostring` / `lua_close`）；`sol2_bridge` 是 sol2+LuaJIT 的功能自检（`self_test`），纯测试用途。二者都将被整合/替换。
- **集成层不变**：`find_package(sol2 CONFIG)`、链接 `sol2::sol2`、`<sol/sol.hpp>` 等基础接入（需求 `20261001-02` 已落地）**保留**，只是 sol2 的使用位置从「自检」迁移到「持久引擎」内部。
- **需遵守已实测的 sol2 踩坑结论**（需求 `20261001-01/02`）：
  1. 必须用**无参 `open_libraries()`**（等价 `luaL_openlibs`）才能把 `jit` 注册为全局变量；带参重载只写 `package.loaded`，导致 `jit.version` 为 nil 崩溃。
  2. 容器参数**按值传**（如 `std::vector<int>`），引用传参会走 usertype 取值路径导致空指针崩溃。
  3. 遵循 ADR-5：sol2 头文件**仅在 `.cpp` 中 include**，不向应用层暴露；引擎公开头文件只暴露标准类型。

### 3. 新引擎接口设计（`script/lua_engine`）

将 `lua_runner` 与 `sol2_bridge` 合并重构为单一持久引擎模块，命名空间 `lua_engine`：

```cpp
// core/script/lua_engine.h
#pragma once
#include <memory>
#include <string>

namespace lua_engine {

    // 基础类型值包装: 隔离 sol2 类型, 应用层不直接接触 sol::object (ADR-5)。
    class Value {
    public:
        bool is_nil() const;
        bool is_bool() const;        bool as_bool() const;
        bool is_number() const;      double as_number() const;
        bool is_string() const;      std::string as_string() const;
    };

    class Engine {
    public:
        Engine();                                     // 构造 sol::state + open_libraries() (无参, 见 §1)
        ~Engine();

        Engine(const Engine&) = delete;
        Engine& operator=(const Engine&) = delete;

        // 加载并执行一个 .lua 文件; 出错经 app_log::error 输出并返回 false。
        bool do_file(const std::string &path);
        // 重新执行已加载的文件 (手动基础重载, 覆盖全局量; 函数级/自动监听热重载留到 P7)。
        bool reload(const std::string &path);
        // 调用全局函数并返回基础类型值; P0 仅支持无参调用, 参数/对象绑定在 P0-04 扩展。
        Value call_function(const std::string &name);

    private:
        struct Impl;                                  // pimpl: 持有 sol::state, 隔离 sol2 头
        std::unique_ptr<Impl> impl_;
    };
}
```

要点：

- `Impl` 采用 pimpl（`std::unique_ptr` + 前置声明），`sol::state` 仅存在于 `lua_engine.cpp`，公开头文件不含 sol2（ADR-5）。
- `do_file` / `reload` 用 `sol::state::script_file`（错误经 `protected_function_result` 捕获），失败信息经 `app_log::error` 输出并返回 `false`。
- `reload` 与 `do_file` 在 P0 阶段语义等价（重新执行文件 chunk，覆盖全局量），后续 P7 再做函数级热重载。
- `Value` 用于把 `sol::object` 收敛为 nil/bool/number/string 四类基础类型，满足 P0 验收「调用函数返回正确值」。

### 4. 旧测试代码清理范围

1. **删除** `script/lua_runner.{h,cpp}`（一次性 `eval_string`，被 `lua_engine` 替代）。
2. **删除** `script/sol2_bridge.{h,cpp}`（`self_test` 自检，纯测试用途，被持久引擎取代）。
3. **删除** `tests/test_lua_runner.cpp`、`tests/test_sol2_bridge.cpp`（对应旧接口测试，替换为 `test_lua_engine.cpp`）。
4. **删除** `app/model_viewer_game.cpp` 中的启动自检（`init()` 内 `lua_runner::eval_string(...)` 的 LuaJIT 版本打印 + `sol2_bridge::self_test()` 报告）、对应成员 `luaMessage_` / `sol2Report_`、以及 ImGui 面板的「LuaJIT + sol2」折叠组、相关 `#include`。

> 说明：上述启动自检为需求 `20261001-01/02` 的验证载体，属「测试用的无用代码」，持久引擎落地后无保留价值。

### 5. `lua/` 文件夹与路径解析

- 新增项目根目录 `lua/`，所有 `.lua` 脚本统一存放于此，临时/测试脚本亦放此处（命名以 `test_` 或 `_tmp_` 前缀区分）。
- **路径解析**：引擎 `do_file(path)` 接收显式路径，解析职责在调用方。
  - **运行时**：复用 `asset_path::resolve()` 思路定位 `lua/xxx.lua`（P0 阶段暂不接入，供后续 P0-09 端到端使用）。
  - **单元测试**：无头环境不能依赖 raylib 的 `FileExists/GetApplicationDirectory`，故由 CMake 通过 compile definition 将 `lua/` 目录**绝对路径**注入测试目标（如 `PROJECT_PHOENIX_LUA_DIR="${CMAKE_SOURCE_DIR}/lua"`），测试据此拼接脚本完整路径，与工作目录无关。
  - reload 测试动态写入临时脚本（`lua/_tmp_reload.lua`），测试结束后删除，避免污染仓库。
