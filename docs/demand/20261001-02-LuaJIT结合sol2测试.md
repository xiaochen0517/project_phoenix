## 需求背景

上一需求 (20261001-01) 已将脚本引擎由 PUC Lua 切换为官方 LuaJIT, 但 `script/lua_runner` 仍直接使用 Lua C API, 手写绑定成本高、易出错。为后续承载游戏脚本 (C++ 侧类型/函数暴露给脚本), 需要引入 C++ 绑定库, 并验证其与 LuaJIT 的适配。

选定 **sol2**: 当前最主流、生态最大的 C++ Lua 绑定库, header-only, 对 LuaJIT 有一等支持 (自动处理 Lua 5.1 API 差异, 提供 `sol::lib::jit` / `sol::lib::ffi`), C++17 可用。

## 需求目标

1. 引入 **最新稳定版 sol2 (v3.5.0)**, 完成 CMake 接入。
2. 实现一个**完整的绑定自检功能**, 覆盖 sol2 核心能力, 验证与 LuaJIT 完美适配 (JIT 可用、双向调用、usertype、容器、异常)。
3. 自检结果在启动时输出到日志, 并在 ImGui 面板中展示。

## 设计方案

### 1. 依赖切换 (vcpkg + CMake)

- `vcpkg.json`: 新增 `"sol2"` 依赖 (header-only, baseline 固定为 3.5.0)。
- 顶层 `CMakeLists.txt`: 新增 `find_package(sol2 CONFIG REQUIRED)` (vcpkg sol2 port 提供 target `sol2::sol2`)。
- `core/CMakeLists.txt`: 链接 `sol2::sol2`; 新增源文件 `script/sol2_bridge.cpp`。

> 说明: sol2 为 header-only, 仅需 `#include <sol/sol.hpp>`; 运行时仍链接已接入的 LuaJIT (`lua51.lib`)。sol2 通过 LuaJIT 头文件中的 `LUAJIT_VERSION` 宏自动识别并启用 JIT 相关能力, 无需额外配置。

### 2. 模块设计 (第三方库隔离封装)

新增 `core/script/sol2_bridge.{h,cpp}`, namespace `sol2_bridge`, 与 `lua_runner` 平级, 隔离 sol2 头文件:

```cpp
// sol2_bridge.h
namespace sol2_bridge {
    // 运行 sol2 + LuaJIT 绑定自检, 返回逐项 PASS/FAIL 与统计摘要
    std::string self_test();
}
```

内部使用 `sol::state` (自持 `lua_State`), 经无参 `open_libraries()` (等价 `luaL_openlibs`) 打开全部标准库 (含 jit / ffi), 逐项执行并累积结果。

### 3. 自检场景 (覆盖 sol2 核心能力)

| # | 场景 | 验证点 |
|---|---|---|
| 1 | JIT 经 sol2 可用 | `jit.version` 非空、`jit.status()` 为 true |
| 2 | C++ 函数 → Lua 调用 | `set_function` 绑定 lambda, `lua.script` 返回结果 |
| 3 | Lua 函数 → C++ 调用 (多返回值) | `sol::protected_function` + `protected_function_result::get<i>` |
| 4 | usertype 绑定 C++ 类 | `new_usertype` + `sol::constructors`(多构造) + 成员函数 + 成员变量 |
| 5 | 容器 `std::vector<int>` 往返 | Lua table 与 C++ 容器自动转换 |
| 6 | 异常处理 | `lua.script(code, sol::script_pass_on_error)` / `protected_function` 捕获错误不抛异常 |

## 实现要点与踩坑 (2026-10-01)

1. **jit 全局变量**: sol2 带参 `open_libraries(..., sol::lib::jit)` 对 jit 用 `luaL_requiref(L, "jit", luaopen_jit, 0)` (`glb=0`), 只写入 `package.loaded` 而不创建全局 `jit`, 导致 `jit.version` 为 nil、`get<std::string>()` 空指针崩溃。改用无参 `open_libraries()` (等价 `luaL_openlibs`), 与 `lua_runner` 同路径, 完整加载 jit 为全局。
2. **容器参数必须按值传**: `const std::vector<int>&` (引用) 会令 sol2 走 usertype 取值路径 (`as_value_tag<T>`), 对 table 调 `lua_touserdata` 得空指针而崩溃; 改为按值 `std::vector<int>` (或 `sol::as_table_t`) 后 sol2 才走 table→容器转换。
