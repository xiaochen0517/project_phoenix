## 需求背景

P0-08 已落地相机骨架：`camera/` 纯逻辑核心（`Params` / `Manager` / `apply_isometric`，单类型 `Isometric`）+ raylib 适配层 `camera_raylib.h` + `api.camera.*` 基础绑定（`get_active` / `switch` / `set_param` / `list`，`shake` / `set_follow` 占位返回 false）。

P1-03 已落地移动与碰撞（`movement/` + `ecs/components.h` 的 `Position`/`Mover`），`world_scene` 中相机为**硬跟随**（`syncCameraToPlayer` 直接 `set_param_active("target_*", pos)`，无平滑），相机实例为**硬编码 Params**。roadmap P1-04 要求补齐：类型扩展（透视 + 正交 isometric）、配置加载、跟随与平滑、`api.camera.set_follow` 实装、正交投影适配。

用户确认（2026-10-03）：
- 相机**配置走 JSON 文件**（对齐现有 `config/` 体系），**Lua 侧只承载逻辑类功能**（相机切换 / 属性切换等）。
- `type` 迁入 `Params`（两类相机参数结构差距小，见 §0-1 分析）。
- 平滑采用指数平滑；`set_follow` 按工程实际设计完整接口面（不追求最小面）。

## 需求目标

1. `Type` 扩展 `Isometric`（透视）+ `IsometricOrtho`（正交），`type` 迁入 `Params`；`apply_isometric` 对两类推导位置，创建时按类型写默认 `projection`。
2. 相机配置改由 **JSON 文件** 加载（`config/camera.json`），解析两类相机条目、默认参数与跟随平滑参数。
3. 实装 `set_follow(entity, smoothing)` 与平滑跟随：每 tick 向目标实体 `Position` 指数平滑逼近，`apply_isometric` 联动重算位置。
4. `api.camera` 补齐逻辑类接口：`set_follow` 真实现 + `clear_follow` + `set_type` / `get_type`（`shake` 继续占位）。
5. `world_scene` 接入：JSON 配置创建相机 + 平滑跟随替换硬跟随 + ImGui 可调平滑/切换类型。
6. 单元测试覆盖纯逻辑、配置解析与绑定；运行侧验证两类相机切换与平滑跟随观感。

## 设计方案

### 0. 关键决策（本需求定案）

1. **`type` 迁入 `Params`（分析结论）**：两类相机参数结构**无类型专属字段**——`pos/target/up/distance` 同构同义（`distance` 均推导位置），`fovy` 同形（仅语义不同：透视 = 视场角、正交 = 垂直视野世界单位），`projection` 仅默认值不同。参数差距小，故按「差距小则 type 放 Params」原则：`Params` 增加 `Type type`，`Manager::create(name, params)` 签名简化（type 取自 `params.type`），同步更新全部调用点（`world_scene` 1 处、`model_viewer_game` 3 处、`demo_scene` 2 处、相机测试）。
2. **配置走 JSON（`config/camera.json`）**：复用既有 `config::Document`（pimpl 隔离 nlohmann/json，ADR-5）；解析器放 `camera/camera_config.{h,cpp}`（依赖 `config::Document`，第一方类型，不破坏 `camera.h/.cpp` 仅标准库的约束）。Lua 侧不做配置，只做逻辑（`switch` / `set_param` / `set_follow` / `set_type`）。
3. **正交投影语义**：`IsometricOrtho` 位置推导与 `Isometric` 相同（`pos = target + kIsoDir * distance`）；创建/`set_type` 时按类型写默认 `projection`（透视 0 / 正交 1，raylib `CAMERA_PERSPECTIVE` / `CAMERA_ORTHOGRAPHIC` 枚举值已对齐）；正交下 `fovy` 语义 = 垂直视野世界单位（raylib `rlOrtho` 的 top = fovy/2），两类默认值在 JSON 配置中分别给出。
4. **跟随方式（运行侧定案）**：核心层提供两档——`follow_tick`（指数平滑 `factor = 1 - exp(-smoothing * dt)`，帧率无关、纯函数可单测）与 `follow_hard`（target 直写、无平滑）。**`world_scene` 采用实时跟随 `follow_hard`**（用户 2026-10-03 运行验证确认：默认平滑参数观感过慢，取消平滑改实时跟随）；平滑能力保留在 `camera/` 供后续镜头特效复用。
5. **跟随数据流**：配置只声明 `follow.smoothing`；`entity` 由 C++ 运行时 `set_follow` 指定（P1-05 `api.ecs` 未落地前 Lua 侧没有稳定 entity id 来源）；每 tick 由场景 C++ 从 `ecs` 读 `Position` 驱动 `follow_hard`。`camera/` 核心**不 include entt**（entity 以 `uint32` 存储，对齐 ADR-9 / ADR-16）。
6. **`set_follow` 完整接口面**：支持 id / 名称 / 活动相机三种作用对象 + `clear_follow` + `follow` 状态查询；首次绑定（或切换 entity）下一 tick **直接 snap** 到目标位置（避免从原点飘移），同 entity 重设 smoothing 不 snap。

### 1. `camera/` 核心扩展（纯逻辑，可无头测试）

`camera/camera.h` 变更：

```cpp
enum class Type {
    Isometric,      // 透视 isometric (projection 默认 0, fovy = 视场角度数)
    IsometricOrtho, // 正交 isometric (projection 默认 1, fovy = 垂直视野世界单位)
};

// 类型名映射 (JSON 配置 / Lua 绑定 / UI 共用)。
std::optional<Type> type_from_name(const std::string& name); // "isometric" / "isometric_ortho"
const char* type_name(Type type);

struct Params {
    Type type = Type::Isometric; // 迁入: 单一事实来源, 创建/切换类型读写
    float pos[3]{8.0f, 6.0f, 10.0f};
    float target[3]{0.0f, 0.0f, 0.0f};
    float up[3]{0.0f, 1.0f, 0.0f};
    float fovy = 45.0f;
    int projection = 0;
    float distance = 10.0f;
};

struct Follow {                 // 跟随状态 (纯数据)
    bool enabled = false;       // 启用标志 (entt 首个实体 id 为 0, 不能以 entity==0 作哨兵)
    std::uint32_t entity = 0;   // 目标实体 (entt entity 的 uint32 语义, 不 include entt)
    float smoothing = 0.0f;
    bool pending_snap = false;  // 首次 tick 直接跳到位
};

// 平滑纯函数 (可单测)。
float smooth_factor(float smoothing, float dt);            // 1 - exp(-smoothing*dt)
void smooth_step(float cur[3], const float target[3], float factor); // cur = lerp(cur, target, factor)
```

`camera::Manager` 变更：

- `Id create(const std::string& name, const Params& params)`：**签名简化**（type 取自 `params.type`）；按类型写默认 `projection`（Isometric→0 / IsometricOrtho→1）；`apply_isometric` 推导位置；名称冲突返回 `kInvalidId`（不变）。
- `bool set_type(Id id, Type type)` + `set_type(name, Type)` + `set_type_active(Type)`：切换类型 → 按新类型重写默认 `projection` → `apply_isometric`；未知 id/名称返回 false。
- `bool set_follow(Id id, std::uint32_t entity, float smoothing)` + `set_follow(name, ...)` + `set_follow_active(...)`：`smoothing <= 0` 经 `app_log::error` 返回 false；首次绑定或 entity 变化置 `pending_snap`（**entity 0 是合法实体**，清除跟随用 `clear_follow`），同 entity 重设 smoothing 不 snap。
- `bool clear_follow(Id id)` + `clear_follow(name)` + `clear_follow_active()`。
- `const Follow* follow(Id id) const`：跟随状态查询（供 UI / 单测）。
- `bool follow_tick(Id id, const float target[3], float dt)`：无跟随返回 false；`pending_snap` 时 target 直写并清标志，否则三分量 `smooth_step(cur, target, smooth_factor(smoothing, dt))`；随后 `apply_isometric` 重算 position；`dt <= 0` 直接返回 false。
- `bool follow_hard(Id id, const float target[3])`：**实时跟随**——target 直写 + `apply_isometric` 重算 position；未启用跟随 / 相机不存在返回 false（`world_scene` 运行时跟随路径）。
- `set_param` 两类相机保持 isometric 联动（`type` 两个取值均走 `apply_isometric`）；`projection` 仍可经 `set_param` 手动覆盖（文档注明）。

`camera/camera_raylib.h`：无需代码改动（`projection` 已直拷，0/1 与 raylib 枚举对齐）；注释补正交说明。

### 2. 相机配置（`config/camera.json`，新增）

```json
{
  "active": "world",
  "cameras": [
    { "name": "world",       "type": "isometric",       "distance": 18, "fovy": 45, "follow": { "smoothing": 0.15 } },
    { "name": "world_ortho", "type": "isometric_ortho", "distance": 18, "fovy": 18, "follow": { "smoothing": 0.15 } }
  ]
}
```

- 字段：`name` 必填非空；`type` 枚举 `"isometric" | "isometric_ortho"`（缺失默认 `"isometric"`）；`distance` / `fovy` 可选（默认 10 / 45）；`follow.smoothing` 可选（缺失 = 不启用跟随；运行侧实时跟随暂不使用平滑，字段保留供后续镜头特效）；`active` 可选（缺失 = 第一个相机名）。
- 校验失败（缺 `cameras` / 缺 `name` / 非法 `type` / `smoothing <= 0`）经 `app_log::error` 输出并返回 `nullopt`。
- 默认距离：透视 18（2026-10-03 运行验证后由 30 调近，观感固化值）。

## 确认结果 (2026-10-03)

1. **type 归属**：用户要求先分析两类相机参数差距——结论为参数同构（无类型专属字段，仅 projection 默认值与 fovy 语义不同），差距小 → `type` 迁入 `Params`（§0-1）。
2. **配置格式**：用户确认相机配置走 **JSON**（`config/camera.json`），Lua 只承载逻辑类功能（切换/属性修改）（§0-2）。
3. **正交参数语义**：接受「distance 仍推导位置、正交 fovy = 垂直视野世界单位」（§0-3）。
4. **平滑算法**：初版接受指数平滑 `1 - exp(-smoothing·dt)`；运行验证用户反馈「跟随过慢、反应迟钝」（smoothing 0.15 @30Hz 时间常数 ≈ 6.7s）→ **改为实时跟随 `follow_hard`**，平滑能力保留在核心层（§0-4）。
5. **set_follow 接口面**：用户授权按工程实际设计完整接口面（§0-6 / §1）。
6. **运行验证问题修复**：① 相机不跟随——根因 entt 首个实体 id 为 0，旧实现以 `entity==0` 作「清除跟随」哨兵误判，改 `Follow.enabled` 显式标志；② 距离过远——默认 distance 30 → 18。
