## 需求背景

P0-01 ~ P0-08 已落地依赖与构建、应用框架与主循环、Lua 引擎、`api.*` 绑定、事件总线、配置系统、ECS 骨架、相机系统骨架，且各纯逻辑层均有单元测试（34 用例 / 125 断言全 PASS）。但当前运行程序 `app/ModelViewerGame` 只接入了 `lua_engine` + `camera`（`register_all` + `register_camera` + `do_file(demo_camera.lua)`），`event/`、`config/`、`ecs/` 三个模块在运行侧**尚未接线**，三层边界「C++ / Lua / 配置」还没形成一次**可见的闭环**。

P0-09 是 P0 骨架的收官需求：把各层串起来，验证「C++ 读配置并驱动初始化 → Lua 订阅/处理事件 → C++ 触发事件 → Lua 调 API 改状态」这条链路真实跑通，且日志 + 画面均可观察。

## 需求目标

1. 新增一个**独立 demo 场景**（归入 `scene/` 场景目录），程序默认进入该场景，并可在 ImGui 中**切换回原模型查看器**。
2. C++ 侧跑通端到端链路：
   - `config::load_file` 加载 JSON 配置并解析（**配置仅供 C++ 核心使用，不经 Lua、不新增 `api.config`**）；
   - 注册 `api.event`，Lua 脚本订阅事件；
   - ECS（**C++**）创建玩家实体；
   - C++ `emit` 触发事件 → 同步分发到 Lua handler → Lua 处理并调 `api.camera.switch`。
3. 日志 + 画面均可观察闭环（运行验证）。

## 关键决策（本需求定案）

1. **配置由 C++ 处理，不新增 `api.config`**：demo 场景在 C++ 侧 `config::load_file(asset_path::resolve(...))` 加载并解析，读取相机参数 / 玩家出生点等字段用于初始化；Lua 不读配置。
2. **ECS 由 C++ 使用，不新增 `api.ecs`**：demo 场景用 `ecs::Registry` 创建玩家实体并挂一个 demo 局部组件（如 `Position`）；`api.ecs` 留后续需求再接入。
3. **独立场景 + 统一顶部选择器**：新增场景切换载体 `app::SceneHost`（实现 `Game`，持有多个命名场景并委托给活动场景，渲染帧内绘制统一顶部选择器）+ 独立场景 `scene::main_game::DemoScene`。场景按大类分目录组织在 `scene/` 下（`menu` / `debug` / `main_game`，用 `scene::` 子命名空间），默认展示 `main_game/demo`，原模型查看器归入 `scene::debug::ModelViewerGame`（`scene/debug/`），通过顶部选择器切换进入。

## 设计方案

### 1. 场景切换载体 `app::SceneHost`（`app/scene_host.{h,cpp}`）

- `SceneHost : public Game`，内部持有 `{name, unique_ptr<Game>, bool initialized}` 列表，`add(name, scene)` 注册，`switch_to(name)` 切换活动场景，`active()` 返回当前场景。
- **场景命名（两级）**：场景名采用「大类/场景名」，如 `debug/model_viewer`、`main_game/demo`；`switch_to` 接受完整名，可在**任意大类间自由切换**，一类可含多个场景。
- `init()/update()/render()/renderUi()/shutdown()` 委托给活动场景；`switch_to` 时对**尚未初始化**的目标场景执行懒 `init()`。
- **默认场景** = `main_game/demo`（启动即展示）；`debug/model_viewer` **懒初始化**（首次切换时才 `init()`，避免启动即加载 26MB 模型）。
- **统一顶部场景选择器**：`SceneHost` 在渲染帧内绘制一个顶部场景选择器（ImGui 主菜单栏/顶部窗口），按大类分组列出全部场景，点击切换；选择器始终可见，不依赖具体场景自身绘制。
- **渲染帧所有权上移**：为支撑统一顶部选择器，`Game` 接口拆分渲染职责（见 §1.1），`SceneHost::render` 负责 `BeginDrawing`/`EndDrawing` 与 `rlImGuiBegin/End`，并在其中依次调用活动场景的 3D 渲染、场景面板与顶部选择器。

### 1.1 `Game` 接口调整（渲染帧所有权上移）

为支撑统一顶部选择器，`app::Game` 接口拆分为 3D 渲染与 UI 两个职责，帧所有权（`Begin/EndDrawing` + `rlImGuiBegin/End`）上移到 `SceneHost`：

```cpp
class Game {
public:
    virtual ~Game() = default;
    virtual bool init() = 0;
    virtual void update(float fixedDt) = 0;
    virtual void render(float alpha) = 0;  // 3D 内容 (ClearBackground + BeginMode3D/EndMode3D), 不含帧所有权与 ImGui
    virtual void renderUi() = 0;           // 本场景 ImGui 面板 (host 在 rlImGuiBegin/End 之间调用)
    virtual void shutdown() = 0;
};
```

`SceneHost::render(alpha)` 流程：

```cpp
BeginDrawing();
active_->render(alpha);          // 场景 3D 内容
rlImGuiBegin();
renderSceneSelector();           // 统一顶部场景选择器
active_->renderUi();             // 场景自身面板
rlImGuiEnd();
EndDrawing();
```

- `ModelViewerGame` 与 `DemoScene` 由「全帧渲染」改为「3D + UI 拆分」：原 `render()` 里的 `BeginDrawing` / `ClearBackground` / `rlImGuiBegin` / `rlImGuiEnd` / `EndDrawing` 上移到 `SceneHost`，`render()` 保留 3D（相机控制、`scene_.update`、网格/模型绘制），原 ImGui 面板拆为独立 `renderUi()` 实现。

### 2. 独立 demo 场景 `scene::main_game::DemoScene`（`scene/main_game/demo_scene.{h,cpp}`）

`scene::main_game::DemoScene : public app::Game`，持有：

- `lua_engine::Engine lua_`
- `event::Bus bus_`
- `camera::Manager cameraManager_`
- `ecs::Registry registry_`
- 玩家实体句柄 + 出生位置（供渲染占位方块）
- 活动相机的 raylib `Camera3D` 副本（渲染用）

`init()` 流程（链路主体）：

1. `config::load_file(asset_path::resolve("config/demo_scene.json"))` 加载配置；解析失败则 `app_log::error` 并回退默认值，不崩溃。
2. 读配置：相机（`default` / `overview` 的 distance / fov）与玩家出生点 `player.{x,y,z}`。
3. 创建两个 isometric 相机（参数来自配置），`set_active("default")`。
4. `api::register_all(lua_)` + `api::register_event(lua_.raw_state(), bus_)` + `api::register_camera(lua_.raw_state(), cameraManager_)`。
5. `lua_.do_file(asset_path::resolve("lua/demo_scene.lua"))` —— 脚本 `api.event.on("player_spawn", handler)` 订阅事件。
6. ECS 创建玩家实体：`auto e = registry_.create(); registry_.attach<Position>(e, {x,y,z})`。
7. 触发事件：`bus_.emit("player_spawn", event::Value::number(entity_id))` —— 同步分发到 Lua handler → handler 打印日志并 `api.camera.switch("overview")`。
8. 渲染相机同步为活动相机：`camera_ = camera::to_camera3d(*cameraManager_.active_params())`。

`render(alpha)`：`ClearBackground` + 活动相机驱动 `BeginMode3D` + `DrawGrid` + 玩家出生点 `DrawCube` 占位方块（使相机切换效果可见）；`renderUi()` 面板显示实体数 / 活动相机。

`update(fixedDt)`：P0 阶段无固定步长业务，no-op（同 `ModelViewerGame`）。

### 3. 配置资产 `config/demo_scene.json`（新增，运行时配置）

```json
{
  "scene": "demo",
  "camera": {
    "default":  { "distance": 18, "fov": 45 },
    "overview": { "distance": 32, "fov": 35 }
  },
  "player": { "x": 0, "y": 0, "z": 0 }
}
```

### 4. 脚本资产 `lua/demo_scene.lua`（新增，运行时脚本）

```lua
api.log.info("demo_scene: init")

local function on_player_spawn(entity_id)
    api.log.info("demo_scene: player spawned, entity_id=" .. tostring(entity_id))
    api.camera.switch("overview")
    api.log.info("demo_scene: switch -> active=" .. api.camera.get_active())
end

api.event.on("player_spawn", on_player_spawn)
```
