> 状态: 已完成 (2026-10-01)

> 关联: `docs/roadmap/P0骨架需求拆分.md`(P0-02)、`docs/项目架构文档.md`(§8 已知问题「主循环/UI 集中在 main.cpp」、§9 应用框架层)

## 需求背景

当前 `core/main.cpp` 承担了全部职责：窗口初始化、ImGui 设置、模型加载、相机控制、ImGui 面板、主循环与退出逻辑（约 430 行，见架构文档 §8 已知问题）。所有逻辑以**帧率相关**的 `GetFrameTime()` 推进，无法为后续「ECS / 事件 / 脚本逻辑」提供稳定的固定步长更新。

P0 骨架要求「程序以固定 tick 推进」作为总验收标准之一，因此需要：

1. 拆分 `main.cpp`，引入 App 生命周期，把「框架外壳」与「业务内容」分离。
2. 落地固定 tick 累加器（`FIXED_DT = 1/30`），逻辑以 30Hz 固定步长更新，渲染侧用插值系数 `alpha` 平滑。
3. 将现有模型查看器作为 P0 阶段的运行载体迁移进 `app/`，**不新增业务**，仅验证框架可用。

## 需求目标

1. 新增 `core/app/` 模块，定义 `App` / `Game` 生命周期（`init()` → 主循环 → `shutdown()`）。
2. 用累加器驱动固定 30Hz 逻辑更新，渲染侧接收 `alpha ∈ [0,1)` 做插值。
3. 将现有模型查看器迁移进 `app/`，`main.cpp` 瘦身为「初始化日志 + 创建 App + run」。
4. 日志可观察逻辑以 30Hz 推进（累计 `update` 次数 ≈ 运行秒数 × 30）。

## 设计方案

### 1. 目录与文件结构

```
core/
├── main.cpp                      // 瘦身: app_log::init() + 创建 App + app.run()
├── app/                          // 新增: 应用框架层
│   ├── game.h                    // app::Game — 业务载体抽象接口 (纯虚)
│   ├── app.h / app.cpp           // app::App  — 应用外壳 (窗口/主循环/固定 tick)
│   ├── model_viewer_game.h       // app::ModelViewerGame — 迁移现有模型查看器 (实现 Game)
│   └── model_viewer_game.cpp
├── util/                         // 新增: 通用工具模块
│   └── asset_path.h / asset_path.cpp  // resolveAssetPath (抽自 main.cpp)
├── log/ / script/ / model/       // 不变
└── tests/                        // 不变 (本需求不新增测试, 属运行验证)
```

### 2. 接口约定

`app::Game`（业务载体抽象接口，后续 P0-09 及更后阶段可替换为真实游戏场景）：

```cpp
namespace app {
class Game {
public:
    virtual ~Game() = default;
    virtual bool init() = 0;               // 业务初始化 (窗口已就绪后调用)
    virtual void update(float fixedDt) = 0; // 固定 30Hz 逻辑更新
    virtual void render(float alpha) = 0;   // 渲染 + ImGui (alpha 插值系数)
    virtual void shutdown() = 0;            // 业务卸载 (窗口关闭前调用)
};
}
```

`app::App`（框架外壳，不依赖具体业务）：

```cpp
namespace app {
class App {
public:
    explicit App(std::unique_ptr<Game> game);
    int run();   // 初始化窗口/ImGui → 固定 tick 主循环 → 卸载
private:
    std::unique_ptr<Game> game_;
};
}
```

- `App` 负责与 raylib / rlImGui 直接交互：`InitWindow`、`SetTargetFPS(60)`、CJK 字体设置（迁移 `setupImGui()`）、`rlImGuiSetup/Shutdown`、`CloseWindow`。
- `Game` 及 `ModelViewerGame` 不直接 `#include` raylib 头之外的第三方头，保持边界清晰（延续 ADR-5 思路）。

### 3. 固定 tick 主循环（`App::run`）

采用标准「Fix Your Timestep」累加器模式：

```cpp
constexpr double kFixedDt = 1.0 / 30.0;

int App::run() {
    // ... init 窗口 + ImGui + game_->init()
    double accumulator = 0.0;
    uint64_t tickCount = 0;

    while (!WindowShouldClose()) {
        // 帧时间上限 0.25s, 防止卡顿后累加器死亡螺旋
        const double frameTime = std::min<double>(GetFrameTime(), 0.25);
        accumulator += frameTime;

        while (accumulator >= kFixedDt) {
            game_->update(static_cast<float>(kFixedDt));
            accumulator -= kFixedDt;
            ++tickCount;
        }

        const float alpha = static_cast<float>(accumulator / kFixedDt);
        game_->render(alpha);
    }

    game_->shutdown();
    // ... rlImGuiShutdown + CloseWindow
}
```

要点：

- `update(fixedDt)` 固定步长调用，一次或多次（追帧）；`render(alpha)` 每帧调用一次。
- `alpha ∈ [0,1)` 由 `accumulator / kFixedDt` 计算，当前帧逻辑已推进到 `tickCount` 步后、下一 tick 之间的插值位置，供渲染插值使用。
- 主循环不在 `Game` 内，避免业务层感知窗口/帧率细节。

### 4. 模型查看器迁移（`ModelViewerGame`）

将现有 `main.cpp` 中的以下内容原样迁入 `ModelViewerGame`，语义与行为不变：

- 相机状态（`Camera3D` + 环绕/手动飞行两种模式 + 速度/旋转参数 + 预设视角按钮）。
- 模型状态（`ModelScene`、`Transform`、模型/贴图路径、动画控制、线框/包围盒开关）。
- ImGui 面板（「LuaJIT + sol2」「模型」「相机」折叠组）迁入 `render(alpha)` 内。
- 辅助函数 `resetCamera` / `fitCameraToModel` / `centerModelOnGrid` / `updateManualCamera` 随迁进 `ModelViewerGame`；`resolveAssetPath` 抽出为独立工具模块 `util/asset_path`，供后续 `config/` 等复用。
- 启动自检（LuaJIT 版本 + sol2 self_test 报告）迁入 `init()`；`scene.load` 默认模型 + 默认贴图在 `init()` 内完成。

动画推进位置：现有 `scene.update(GetFrameTime())` 属渲染期逐帧推进。迁移后**保留在 `render(alpha)` 每帧调用**（保证动画平滑，且 `ModelScene` 内部以 60fps 基准），`update(fixedDt)` 当前仅用于累计 tick 计数验证 30Hz。

### 5. 30Hz 推进验证

`update(fixedDt)` 内累计 `tickCount`，`App` 主循环内每累计约 1 秒（或每 30 tick）经 `app_log::info` 输出一次：

```text
fixed tick: count=30, elapsed=1.00s, rate=30.0/s
```

据此人工核对「累计 update 次数 ≈ 运行秒数 × 30」。

## 确认结果 (2026-10-01)

1. **拆分粒度**：采用「`App`(外壳) + `Game`(抽象接口) + `ModelViewerGame`(迁移实现)」三层结构。
2. **动画推进位置**：`scene.update` 保留在 `render`（每帧，平滑），`update(fixedDt)` 仅用于累计 tick 验证 30Hz。
3. **`resolveAssetPath` 归属**：抽出为独立工具模块（`core/util/` 或同类位置），供后续 `config/` 等复用。
