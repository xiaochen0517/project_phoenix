## 需求背景

原 05/06 的透明溶解逻辑（固定南/东墙剔除、underCover 整层跳过、per-cell 南/东裁剪位窄扫描）不满足实际观感要求，且当前运行侧仍存在以下基础问题：

1. **碰撞问题**：墙应当只在其线段边界处阻挡移动，但当前房屋被墙整排围死（无论从墙内一侧还是墙外一侧都无法穿过整排 tile），角色无法进入房屋。
2. **墙高问题**：当前墙高仅 1 渲染单位，房屋矮扁不成比例；且上层墙悬在入口上方（高度 1~2 区间）与角色头部相交。墙应为 3m 高（现实房屋比例，长方形）。
3. **建筑内信息缺失**：当前 map 数据不包含建筑信息，「角色是否在建筑内」只能靠 `has_content_above`（头顶是否有高层内容）推断——单层无顶建筑无法识别为屋内、非建筑悬空结构会被误判为屋内。需在 tile 数据中显式记录「建筑内」标志，读取时一并解析，实现精确的高层溶解与墙面透明判定。

用户已重新描述透明溶解的需求逻辑（见下文「需求分析」），本需求据此**重写**遮挡判定，并修复上述碰撞与墙高问题。原 05 已完成的稀疏 tile 存储、空 tile 语义、地面 2D 渲染、网格描边、自由相机、相机调试**保留不动**。

## 需求分析：透明溶解规则总结

**视角约定**：等距相机固定位于玩家东南上方（`position = target + normalize(1,1,1) * distance`，俯角 ≈ 35°）。屏幕方向：北 = 屏幕上侧、南 = 屏幕下侧、东 = 屏幕右侧、西 = 屏幕左侧；玩家西北方 = 屏幕上方。

**遮挡的几何本质**：相机到玩家的视线在水平面上是东南对角线（dx == dy），沿途高度 ≈ 水平距离 / √2。据此：

- 高层内容位于玩家**东南方向**（dx ≥ 0 且 dy ≥ 0）时会截断视线、遮挡玩家 → 玩家在建筑西/北方（建筑在玩家东南、屏幕前侧）时需要**远距离溶解**高层内容；
- 玩家在建筑东/南方时（建筑在玩家西北、屏幕后方），高层内容不在视线路径上，永不遮挡玩家 → **不溶解**；
- 玩家在屋内时头顶楼板必然遮挡 → 整层溶解；
- 同层墙：朝向玩家的「前后墙」（屏幕下/上侧的南/北墙）会遮挡视线 → 整排透明；位于玩家屏幕左/右侧的东西墙不遮挡 → 保留不透明。

**一句话总结**：房屋不能遮挡玩家视线，且在不遮挡角色的前提下尽可能显示多的墙和建筑。

### 高度模型（本次变更）

z 轴一个层级单位 = 实际渲染 3 个单位（3m）。`level_height` **保持 1.0** 不变，新增世界级垂直缩放 `vertical_scale = 3.0`：

- 层基准渲染高度 = `z × level_height × vertical_scale`（上层基准 = 3.0）；
- 墙渲染高 = `level_height × vertical_scale` = 3.0（3m）；
- 上层墙渲染区间 3.0 ~ 6.0，房屋总高 6m（两层楼比例）；
- tile 立方体高 = `tile_def.height × vertical_scale`；玩家渲染 y = `pos.z × vertical_scale`；
- 水平方向与移动逻辑（`movement::step` 的 `pos.z = z × level_height + tile.height`）**均不变**，缩放只作用于渲染侧。

### 建筑内数据（本次变更）

「屋内」判定改为**数据驱动**，不再推断：

- `tiles` 稀疏条目新增可选字段 `"interior": true`（默认 false），语义 = 该格为建筑内部空间（纯渲染遮挡用，与 walkable / 碰撞无关）；
- `Level` 新增稀疏集合 `interior_tiles`（interior=true 的 tile 组合键）；`World::is_interior(z, tile)` 查询（层级不存在 / 未声明 / 越界 → false）；
- 「屋内」= `is_interior(玩家层, 玩家tile)`；门洞格位于围墙 footprint 内，同样标记 interior；
- 移除 `has_content_above`（旧「屋内」推断接口，随 06 旧溶解逻辑一并删除，含其单元测试）；
- 预留：后续引入建筑 ID / 建筑归属时，由 per-tile 标志升级为建筑实体，判定接口不变。

### 规则 A：高层内容溶解（层级 > 玩家层）

整层判定（不渲染，非半透明），触发条件：

1. **屋内**：玩家所在 tile 被标记为建筑内（`world.is_interior(玩家层, 玩家tile)`）→ 溶解所有更高层；
2. **玩家在建筑西北方**（建筑位于玩家东南象限 = 相机前侧，会遮挡角色）→ **直接**溶解所有更高层，不做距离判定。

**玩家在建筑东南方**（建筑位于玩家西北 = 屏幕后方，永不遮挡角色）→ **不进行任何溶解操作**。（注释预留：后续加入角色视线（LOS）/ 窗户检测后再扩展，当前不涉及。）

判定依据：玩家层存在 `interior` tile 位于玩家东南象限（dx ≥ 0 且 dy ≥ 0）即视为「建筑在玩家东南」。

### 规则 B：同层墙透明（层级 == 玩家层）

1. **屋内**（玩家 tile 被标记为建筑内）：沿玩家所在列/行（并检查相邻行列，覆盖 1 格宽门洞）向南/向东找到**最近的南墙线与东墙线**，这两条墙线上的**全部南墙与东墙整排半透明**（含门洞两侧墙段）；北/西墙保持不透明（位于玩家屏幕后方/左侧，不遮挡视线）。南/东墙位于相机前侧（相机在东南上方），北/西墙在屏幕后方。
2. **玩家在建筑西北方**（建筑位于玩家东南、相机前侧）：**当前层级的所有墙设置为透明**。
3. **玩家在建筑东南方**（建筑位于玩家西北、屏幕后方）：**不进行任何透明操作**。（注释预留：后续加入角色视线（LOS）/ 窗户检测后再扩展，当前不涉及。）

低于玩家层的墙（z < 玩家层）永不隐藏。

> 墙半透明 alpha 为运行期可调常量（沿用原 06 的 80 alpha 观感，后续调参）。

## 需求目标

1. **碰撞语义**：墙 = 边墙线段，只阻挡跨线移动；墙两侧 tile 可正常进入与站立；门洞（墙排缺口）可通行。demo 房屋四面围墙 + 南墙 1 格门洞。
2. **高度模型**：`level_height` 保持 1.0；新增 `vertical_scale = 3.0`（z 轴 1 单位 = 渲染 3 单位 = 3m）；墙渲染高 3m；上层基准 3.0、上层墙 3~6，总高 6m。
3. **建筑内数据**：map tile 增加 per-tile `interior` 标志（读取 tile 数据时一并解析）与 `is_interior` 查询；「屋内」判定数据驱动，移除 `has_content_above` 推断。
4. **透明溶解重写**：按规则 A/B 替换旧逻辑；删除 per-cell 南/东裁剪位窄扫描（`computeCutaway` 行列扫描）与「underCover → 整层跳过」粗粒度判定（`isDissolved`）。
5. **封装**：判定逻辑拆分为独立函数（高层溶解触发、屋内墙线扫描、屋外近距判定），不堆在一个函数里；沿用 06 的 per-cell 裁剪位数据结构（bit 每墙侧），只重写位计算逻辑。

## 设计方案

### 1. 新模块 `core/visibility/`（纯逻辑，可无头单测）

只依赖 `world/` 与标准库，不依赖 raylib / sol2 / ecs（对齐 ADR-9）。裁剪位沿用 06 的 per-cell 标志结构（`uint8_t`，bit0=南、bit1=东、bit2=北、bit3=西），由本模块负责计算，渲染侧只消费。

```cpp
// core/visibility/visibility.h
#pragma once

#include "world/world.h"

#include <cstdint>
#include <unordered_map>

namespace visibility {
// 玩家视角: 水平世界坐标 + 所在层 (z)。
struct View {
    float x = 0.0f;
    float y = 0.0f;
    std::int32_t z = 0;
};

// 每格墙裁剪位 (per-cell, 沿用 06 结构并扩展北/西位)。
inline constexpr std::uint8_t kCutSouth = 0x1;
inline constexpr std::uint8_t kCutEast = 0x2;
inline constexpr std::uint8_t kCutNorth = 0x4;
inline constexpr std::uint8_t kCutWest = 0x8;

// 渲染遮挡判定 (纯逻辑): 规则 A (高层溶解) + 规则 B (同层墙透明)。
class Culler {
  public:
    // 每固定 tick 重算。
    void update(const world::World& world, const View& view);

    // 规则 A: 所有更高层 (z > 玩家层) 是否整层溶解 (不渲染)。
    bool upper_dissolved() const { return upper_dissolved_; }

    // 规则 B: 墙是否隐藏 (仅玩家层有效; 其他层返回 false, 层级处理由调用方负责)。
    bool is_wall_hidden(const world::Wall& wall) const;

  private:
    // 规则 A: 屋内 / 建筑位于玩家东南 (相机前侧) 两触发。
    void compute_upper_dissolve(const world::World& world);
    // 规则 B: 屋内南北墙线整排置位 + 屋外建筑位于玩家东南时当前层全部墙置位。
    void compute_wall_cutaway(const world::World& world);
    // 屋内: 沿玩家列 (含相邻列, 覆盖 1 格门洞) 找最近墙线; 返回墙线坐标。
    bool find_wall_line(const world::World& world, bool south, float& line) const;
    // 玩家层是否存在建筑内 tile 位于玩家东南象限 (dx >= 0 && dy >= 0), 即建筑处于相机前侧。
    bool has_building_southeast(const world::World& world) const;

    bool upper_dissolved_ = false;
    bool building_se_ = false; // 建筑位于玩家东南 (相机前侧) 的触发标志
    std::int32_t player_z_ = 0;
    world::TileCoord player_tile_{};
    std::unordered_map<std::int64_t, std::uint8_t> wall_flags_; // tile_key(cell) -> 裁剪位
};
} // namespace visibility
```

实现要点：

- `update`：缓存 `player_z_` / `player_tile_`；`building_se_ = has_building_southeast(world)`（遍历玩家层 `interior_tiles`，存在 tile 位于玩家东南象限即视为建筑在相机前侧）；清空 `wall_flags_` 后依次调用 `compute_upper_dissolve` 与 `compute_wall_cutaway`。
- `compute_upper_dissolve`：规则 A —— ① 屋内（`is_interior(玩家层, 玩家tile)`）→ 溶解；② `building_se_` → 直接溶解（无距离判定）；③ 否则不溶解（玩家在建筑东南方；注释预留后续 LOS/窗户扩展）。
- `compute_wall_cutaway`：遍历玩家层 `walls`：
  - 屋内 → `find_wall_line(南)` / `find_wall_line(北)` 得两条墙线，凡 `side ∈ {N,S}` 且墙线命中（N 墙线 = cell.y、S 墙线 = cell.y + 1）的墙 → 按 side 置位（整排 = 墙线上全部墙，含门洞两侧）；
  - `building_se_`（玩家在建筑西北方）→ 当前层**所有墙**置位（全部透明）；
  - 否则（玩家在建筑东南方）→ 不置位（注释预留后续 LOS/窗户扩展）。
- `find_wall_line`：从玩家 tile 起逐行扫描（南向 `has_wall(..., South)`、北向 `has_wall(..., North)`），每行检查玩家列与相邻两列（覆盖 1 格宽门洞）；扫描上限 = 层级 width/depth（缺失时用固定上限 512）。

### 3. `world_scene` 集成

- 删除：`tileCutaways_` 成员、`computeCutaway`、`underCover` 整层跳过逻辑、`kWallHeight` 常量（含 `kCutawayScan`）。
- 新增成员 `visibility::Culler culler_;`；`update` 内移动后 `culler_.update(*world_, {pos.x, pos.y, mover.z})`。
- 垂直渲染：`baseY = z × level_height() × vertical_scale()`；墙高 = `level_height() × vertical_scale()`；tile 立方体高 = `tile.height × vertical_scale()`；玩家渲染 y = `pos.z × vertical_scale()`。
- `render`：若 `culler_.upper_dissolved()` → 跳过所有 `z > 玩家层` 的层级；玩家层正常 `renderLevel`；低于玩家层正常渲染。
- `renderWalls`：`culler_.is_wall_hidden(wall)` → 半透明色（`kWallColorOccluded`，alpha 80）；**墙面改为 2D 平面**（`DrawPlane` 旋转 90° 立起，非 3D 长方体），渲染在地面 tile 的接缝处（墙线），双面可见。

- ImGui：显示高层溶解状态；相机默认 `distance` 24 → 30（适配 6m 高建筑）。

## 验证方式（单元测试 + 运行验证，沿用 `AGENTS.md`）

## 确认结果 (2026-10-02)

用户已确认下列决策，按此实现：

1. **碰撞与门洞**：墙 = 边墙线段，只阻挡跨线移动，两侧 tile 可进入站立；房屋四面围墙 + 南墙 1 格门洞（x=10），出生点移至房屋南侧正对门洞。
2. **屋内墙规则（v2，运行验证后调整）**：南墙线 + 东墙线整排半透明（含门洞两侧墙段），北/西墙保留不透明（南/东墙位于相机前侧、北/西墙在屏幕后方）。
3. **屋外墙规则（v2，运行验证后调整）**：按玩家与建筑的相对方向二元判定——玩家在建筑西北方（建筑在玩家东南、相机前侧）→ 当前层所有墙透明；玩家在建筑东南方（建筑在玩家西北、屏幕后方）→ 不进行任何透明操作（代码注释预留后续 LOS/窗户扩展）。
4. **高层溶解（v2，运行验证后调整）**：玩家在建筑西北方 → 直接隐藏所有高于当前层级的内容（不做距离判定）；玩家在建筑东南方 → 不进行任何溶解操作。
5. **高度模型**：z 轴 1 个单位 = 实际渲染 3 个单位（3m）；`level_height` 保持 1.0，新增 `vertical_scale = 3.0`；墙渲染高 3m，上层基准 3.0、上层墙 3~6，总高 6m。
6. **建筑内数据**：map tile 增加 per-tile `interior` 标志（读取 tile 数据时一并解析），新增 `is_interior` 查询；「屋内」判定数据驱动，移除 `has_content_above` 推断（含其测试）。

## 遗留（后续需求承接）

- 多建筑场景下「整层溶解 / 整墙线透明」为粗粒度（不区分建筑归属），后续引入建筑 ID（由 per-tile `interior` 标志升级为建筑实体，判定接口不变）后收敛到「当前建筑」。
- 墙半透明 alpha 为经验初值，运行侧验证后固化。
- 玩家在建筑东南方的 no-op 分支已注释预留：后续加入角色视线（LOS）/ 窗户检测后，再扩展对应的溶解/透明逻辑。
- 门洞暂无门模型（纯缺口），门实体与开关后续需求。
