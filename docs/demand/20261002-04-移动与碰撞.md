## 需求背景

P1 总目标「能走的地图」需要把已落地的输入抽象（`input/` 方向动作）、世界与地图（`world/` walkability/边墙/楼梯查询）、ECS 骨架（`ecs/` 实体/组件）串成「角色可移动、撞墙被挡、踩楼梯上下层」的闭环。当前 `demo_scene` 里 `Position` 还是场景局部 struct，移动逻辑未落地，也没有渲染 tile 地图与角色模型的可见表现。

本需求对应 roadmap P1-03，并额外把表现层提前落地（用户明确要求）：加载 `bob_idle` 模型作为玩家、tile 基础渲染、玩家移动观感。纯逻辑（组件 schema、移动与碰撞判定）保持可无头单测；表现层由运行侧世界场景承载，需用户手动验证。

## 需求目标

1. **组件正式化**：把 demo 局部的 `Position` 提升为正式 ECS 组件（含 `x/y/z`），新增 `Mover`（`speed` + `level`）组件。
2. **移动与碰撞纯函数**（可无头单测）：输入方向驱动位移，经 tile walkability + 边墙碰撞，支持楼梯层级切换；与 raylib 无关。
3. **世界场景**：新增运行侧场景，加载 `config/demo_world.json` 地图 + 玩家实体，串起 input → movement → 实体位置。
4. **玩家模型**：加载 `assets/models/body/Bob_Idle.glb`，播放 idle 动画，渲染为玩家。
5. **tile 基础渲染**：按 `tile_def` 的 `color`/`height` 绘制当前层 tile，边墙绘制薄板。
6. **玩家移动效果**：W/A/S/D 在地图上移动，撞不可走 tile / 撞边墙被阻挡，踩楼梯切换层级（肉眼可见）。

## 设计方案

### 1. 总体分层与文件结构

```text
core/ecs/
└── components.h           // 新增: 正式组件 schema (Position / Mover), header-only 纯数据
core/movement/
├── movement.h             // 新增: 移动与碰撞纯函数声明 (依赖 ecs/components.h + world)
└── movement.cpp           // 新增: 碰撞判定实现 (纯逻辑, 无 raylib)
core/scene/main_game/
├── world_scene.h          // 新增: 世界场景 (world + bob_idle + tile 渲染 + 移动)
└── world_scene.cpp        // 新增
core/tests/
└── test_movement.cpp      // 新增: 移动与碰撞单元测试
```

- `core/movement/` 纯逻辑只依赖 `world/` + `ecs/components.h` + 标准库，不依赖 raylib / sol2 / input（依赖方向 input → movement 由场景完成，保持解耦可测）。路径解析职责分离（ADR-14）：`movement/` 只接收已加载的 `world::World` 引用。
- 组件 schema 放 `ecs/components.h`（对齐 roadmap「ecs/ 组件 schema」），供 P1-04 相机跟随、P1-05 `api.ecs` 复用 `Position`/`Mover`，避免它们反向依赖 `movement/`。

### 2. 组件 schema（`ecs/components.h`）

```cpp
namespace ecs {
// 位置组件 (x/z 水平面, y 高度)。
struct Position {
    float x = 0.0f;
    float y = 0.0f;
    float z = 0.0f;
};

// 移动组件: speed = 每秒世界单位, level = 当前层索引 (对应 world::level 的 index)。
struct Mover {
    float speed = 3.0f;
    std::int32_t level = 0;
};
}
```

- header-only 纯数据 struct，`ecs::Registry::attach<Position>` / `attach<Mover>` 直接可用（entt 模板在知道 `T` 完整定义处实例化）。
- 与 `demo_scene` 的局部 `Position` 语义一致，替换后删除局部定义。

### 3. 移动与碰撞纯函数（`movement/`）

```cpp
namespace movement {
// 移动结果。
struct MoveResult {
    bool moved = false;         // 本 tick 是否发生位移
    bool level_changed = false; // 是否触发层级切换
};

// 沿水平方向 (dx, dz)（须为单位向量或由函数内部归一化）尝试移动 pos。
// 碰撞: 目标 tile walkable + 边墙; 命中楼梯则切换 mover.level 而非继续移动。
MoveResult step(const world::World& world, Position& pos, Mover& mover, float dx, float dz, float dt);
}
```

- `step` 是纯函数（无 raylib / 无 IO），是 P1-03 的可单测核心。
- 场景侧职责：采样输入 → `action_to_dir` 合成方向 → 归一化 → `movement::step(...)`；`movement/` 不直接依赖 `input/`。

### 4. 碰撞判定算法（轴分离）

采用**轴分离（X/Z 分轴判定）**，比「单一合成方向」观感更自然（贴墙可滑动、斜向不会卡角）：

1. 归一化 `(dx, dz)` → `(nx, nz)`；步长 `stepX = nx * speed * dt`、`stepZ = nz * speed * dt`。
2. **X 轴**：`newX = pos.x + stepX`；`target = world_to_tile(newX, pos.z)`；当 `stepX != 0` 时检查
   ① `world.is_walkable(level, target)`；② 跨格时 `has_wall`（`stepX > 0` 查 `Side::East`，`< 0` 查 `Side::West`）。
   通过则 `pos.x = newX`，否则保持不动。
3. **Z 轴**：同理（`stepZ > 0` 查 `Side::South`，`< 0` 查 `Side::North`）。
4. 移动后按最终 tile 的 `tile_def.height` 更新 `pos.y`（角色高度贴地）。
5. **楼梯**：若移动后所站 tile 的 `stairs` 为 `Up`/`Down`，则 `mover.level` 相应 +1/-1（越界则忽略），并保持 `(x, z)` 不变、`pos.y` 更新为目标层该格高度，置 `level_changed = true`。

> 高速穿透（roadmap §5 风险项）：MVP 速度慢（speed≈3、dt=1/30，单 tick 位移 ≈0.1 单位，远小于 tile_size=1），单次判定即可，不引入子步进；speed 保持可配置以便后续需要时再评估。

### 5. 世界场景（`scene/main_game/world_scene`）

新增独立场景 `WorldScene`（保留 `DemoScene` 不变），经 `SceneHost` 注册，建议注册在首位成为默认场景，启动即见地图与玩家。

- **init**：
  1. `config::load_file(asset_path::resolve("config/demo_world.json"))` → `world::World::load`。
  2. `input::load_bindings`（`config/input_bindings.json`，上下文 `main_game`），`inputManager_.set_context("main_game")`。
  3. 创建玩家实体：`registry_.attach<Position>`（出生点取地图可走格中心）+ `attach<Mover>`（默认 level=0）。
  4. 加载玩家模型 `asset_path::resolve("assets/models/body/Bob_Idle.glb")`（`model_loader::ModelScene`），播放 idle 动画（`setActiveAnimation(0)` + `setLoop(true)`），并对齐脚底到地面（复用 model_viewer 的 `centerModelOnGrid` 思路）。
  5. 创建 isometric 相机（`camera::Manager`），注册 `api.*`（含 `register_input`），加载场景 Lua（可选，后续接入）。
- **update(fixedDt)**：
  1. `inputManager_.sample(input::sample_pressed_keys())`。
  2. 合成方向：遍历 `move_up/down/left/right`，`state()==Held` 的累加 `action_to_dir`，归一化。
  3. `movement::step(*world_, pos, mover, dx, dz, fixedDt)`。
  4. 相机目标跟随玩家：`set_param_active("target_x/y/z", pos)`（isometric 自动重算 position），同步渲染相机。
- **render(alpha)**：`scene_.update(GetFrameTime())` 推进模型动画；绘制当前层 tile + 边墙薄板 + 玩家模型（位置取 `Position`，保持模型原始 1 单位 = 1 米缩放，仅对齐脚底）。
- **renderUi**：显示 FPS、玩家位置 / 层、活动相机类型、操作提示（W/A/S/D 移动）。

### 6. tile 基础渲染

- 遍历**当前层**（`mover.level`）`width×depth`：每格 `tile_def_at` 取 `color`/`height`，用 `DrawCube`（或 `DrawCubeV`）在 tile 中心绘制 `tile_size × height × tile_size` 的方块；`height==0` 的平地用薄板（或 `DrawPlane`）表现地面，避免视觉漂浮。
- 边墙：遍历 `level.walls`，在 `{cell, side}` 对应边绘制薄板（`tile_size` 长、固定墙高、薄厚）。
- 楼梯 tile 用其颜色 + 略高的小台阶块标记，便于观察上下层入口。

### 7. 玩家模型（bob_idle）

- 复用 `model_loader::ModelScene`，`load("assets/models/body/Bob_Idle.glb")`；该模型已存在（model_viewer 默认加载同一文件）。
- 播放 idle：`setActiveAnimation(0)`（若无动画则保持静态模型）、`setLoop(true)`、`setPlaying(true)`。
- 尺度约定：模型按 1 单位 = 1 米制作（约 1.7 单位高的角色），**保持原始缩放不缩小**；`tile_size = 1.0`（1 单位 = 1 tile），tile 以 1 单位大小渲染，玩家约 1.7 tile 高，符合真实比例。
- 对齐：用 `bounds()` 求本地包围盒，把模型平移使其底面中心落在角色脚底（即 `Position` 处）。
- 渲染：`draw(transform, /*drawWires*/false)`，位置取 `Position`，y 已贴地。

### 9. 单元测试（`tests/test_movement.cpp`）

用 `config/test` 下的小尺寸测试地图（或复用 `test_world.json`），加载 `world::World` 后对 `movement::step` 断言：

| 用例 | 验证点 |
|---|---|
| 直线移动 | 无阻挡时 `pos` 按 `dir * speed * dt` 位移，`moved=true` |
| 整格阻塞 | 目标 tile `walkable=false` → 该轴不移动 |
| 边墙阻挡 | 跨格方向有边墙 → 该轴不移动（对称查询生效） |
| 贴墙滑动 | 斜向移动、X 被挡时 Z 仍可移动（轴分离效果） |
| 楼梯切换 | 踩 `stairs_up` → `level+1` 且 `level_changed=true`；`stairs_down` → `level-1` |
| 层级越界 | 已在最上/最下层再切换 → 忽略，level 不变 |
| 高度贴地 | 移动后 `pos.y` 更新为所站 tile 的 `height` |
