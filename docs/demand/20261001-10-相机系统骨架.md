## 需求背景

P0-01 ~ P0-07 已落地依赖与构建、应用框架、Lua 引擎、`api.*` 绑定、事件总线、配置系统、ECS 骨架。但当前程序还没有一个**可复用的相机模块**：渲染相机目前硬编码在 `app/model_viewer_game.cpp`（一个裸 `raylib::Camera3D camera_` + 环绕/手动调试控制），既没有「多相机实例 / 活动相机」的概念，也没有 `api.camera.*` 绑定，后续的脚本驱动相机（切换视角、摇镜、跟随）无处承载。

P0-09 端到端链路明确包含「调 `api.camera.switch`」这一步，而 roadmap P0-08 验收要求「Lua 配置相机、`switch` 切换、`set_param` 改 FOV/距离后生效」。当前缺失 `camera/` 模块，需要先落地相机骨架。

## 需求目标

1. 新增 `camera/` 模块：多相机实例管理（实例列表 + 活动相机）+ 相机参数（FOV / 距离 / 位置 / 目标 / up / 投影）。
2. 复用 raylib `Camera3D` 概念：纯逻辑参数结构语义对齐 `Camera3D`，经独立适配层转为 `Camera3D`，不污染纯逻辑层（ADR-5 / ADR-9）。
3. 实现一个最小 **isometric 相机**作为验证载体（完整跟随 / 平滑 / 操控放 P1）。
4. 新增 `api.camera.*` 绑定：`get_active` / `get_active_id` / `switch` / `set_param` / `list`（`shake` / `set_follow` 先占位）。
5. 单元测试覆盖验收链（纯逻辑 + Lua 绑定）；最小接线到运行 app，Lua 驱动相机可见生效。

## 设计方案

### 0. 关键决策（本需求定案）

1. **raylib 依赖隔离**：`camera/` 核心为**纯逻辑**（参数结构 + 实例管理 + isometric 位置推导），不 include raylib，可无头单元测试；raylib `Camera3D` 的转换放独立头 `camera/camera_raylib.h`（header-only，仅 `project_phoenix` 目标使用，测试目标不链接）。对齐 ADR-9（无头测试）与 ADR-14（路径解析职责分离）的精神。
2. **相机标识双轨**：同时支持**名称（string）** 与 **id（uint32）** 标识。`create(name, ...)` 返回 id 并登记名称（名称唯一）；`switch` 接受名称或 id；`get_active` 返回名称、`get_active_id` 返回 id；`list` 返回名称表。
3. **`set_param` 键集**：核心 `fov`（等价 `fovy`）与 `distance`（满足验收），并扩展分量键 `pos_x/pos_y/pos_z`、`target_x/target_y/target_z`、`up_x/up_y/up_z`、`projection`。value 用 number（对齐 `event::Value` / `lua_engine::Value` 四类基础类型）。
4. **isometric 语义**：位置由 `position = target + kIsoDir * distance` 推导（`kIsoDir = normalize(1,1,1)`）；改 `distance` / `target` 会联动重算位置，改 `fov` 只改视场角；`pos_x/y/z` 在 isometric 类型下会被推导值覆盖（文档明确）。

### 1. `camera/` 模块（纯逻辑，可无头测试）

新增 `core/camera/camera.h` + `core/camera/camera.cpp`，`namespace camera`，只依赖标准库，**不依赖 raylib / sol2 / lua_engine / config / event**。

```cpp
// core/camera/camera.h
#pragma once

#include <cstdint>
#include <string>
#include <vector>

namespace camera {

using Id = std::uint32_t;
inline constexpr Id kInvalidId = 0;

// 相机类型（可扩展；P0 仅 isometric 验证载体）。
enum class Type {
    Isometric,
};

// 相机参数（纯数据，语义对齐 raylib Camera3D；不依赖 raylib）。
struct Params {
    float pos[3]{8.0f, 6.0f, 10.0f};
    float target[3]{0.0f, 0.0f, 0.0f};
    float up[3]{0.0f, 1.0f, 0.0f};
    float fovy = 45.0f;
    int projection = 0; // 0 = 透视(CAMERA_PERSPECTIVE), 1 = 正交(CAMERA_ORTHOGRAPHIC)
    float distance = 10.0f; // 相机到目标点距离（isometric 用于推导位置）
};

// isometric 位置推导: position = target + kIsoDir * distance（纯函数，可单测）。
void apply_isometric(Params& params);

// 多相机实例管理：名称唯一，同时支持名称与 id 两种标识。
class Manager {
  public:
    // 创建相机，返回 id；名称冲突返回 kInvalidId。
    Id create(const std::string& name, Type type, const Params& params);
    bool destroy(Id id);
    bool destroy(const std::string& name);
    bool has(Id id) const;
    bool has(const std::string& name) const;

    Id find(const std::string& name) const; // 名称→id，不存在返回 kInvalidId
    std::vector<std::string> names() const; // list

    bool set_active(Id id);
    bool set_active(const std::string& name);
    Id active() const;                       // 无活动相机返回 kInvalidId
    std::string active_name() const;         // 无活动相机返回空串

    const Params* params(Id id) const;
    const Params* active_params() const;

    // 按 key 修改参数（作用于指定相机 / 活动相机）；未知 key 返回 false。
    bool set_param(Id id, const std::string& key, double value);
    bool set_param(const std::string& name, const std::string& key, double value);
    bool set_param_active(const std::string& key, double value);

  private:
    struct Instance {
        Id id;
        std::string name;
        Type type;
        Params params;
    };
    std::vector<Instance> instances_;
    Id next_id_ = 1;
    Id active_ = kInvalidId;
};

} // namespace camera
```

要点：

- **`set_param` 与 isometric 联动**：`set_param` 先写参数，若该相机为 isometric 类型，再调 `apply_isometric` 重算位置，保证「改距离/目标 → 位置生效」。键集合：`fov`/`fovy`、`distance`、`pos_x`/`pos_y`/`pos_z`、`target_x`/`target_y`/`target_z`、`up_x`/`up_y`/`up_z`、`projection`；未知 key 经 `app_log::error` 输出并返回 `false`。
- **`kIsoDir = normalize(1,1,1) ≈ (0.57735, 0.57735, 0.57735)`**：经典等距视角方向，常量内联于 `.h`（`constexpr float`），`apply_isometric` 用其做 `target + dir * distance`。

### 2. raylib 适配层（`camera/camera_raylib.h`，header-only）

```cpp
// core/camera/camera_raylib.h
#pragma once

#include "camera/camera.h"
#include "raylib.h"

namespace camera {
// 纯逻辑 Params → raylib Camera3D（字段直拷；调用方负责在需要时先 apply_isometric）。
inline Camera3D to_camera3d(const Params& params) {
    Camera3D c{};
    c.position = {params.pos[0], params.pos[1], params.pos[2]};
    c.target = {params.target[0], params.target[1], params.target[2]};
    c.up = {params.up[0], params.up[1], params.up[2]};
    c.fovy = params.fovy;
    c.projection = params.projection;
    return c;
}
} // namespace camera
```

- 该头只在 `app/`（运行侧）include；`camera/` 核心与测试目标**不** include raylib。
- 由于 isometric 的位置已由 `set_param` 联动推导（§1），`to_camera3d` 只需字段直拷，无需再判断类型。

### 3. `api.camera.*` 绑定（`script/api_registry`）

- `api_registry.h` 新增声明：`void register_camera(lua_State* L, camera::Manager& manager);`（与 `register_event(lua_State*, event::Bus&)` 同构——相机为有状态对象，需外部注入实例）。
- `api_registry.cpp` 新增实现（`#include "camera/camera.h"`）：

```cpp
void register_camera(lua_State* L, camera::Manager& manager) {
    sol::state_view lua(L);
    sol::table api = lua["api"].get_or_create<sol::table>();
    sol::table cam = api["camera"].get_or_create<sol::table>();

    cam["get_active"] = [&manager]() { return manager.active_name(); };
    cam["get_active_id"] = [&manager]() { return static_cast<double>(manager.active()); };

    cam["switch"] = sol::overload(
        [&manager](const std::string& name) { return manager.set_active(name); },
        [&manager](double id) { return manager.set_active(static_cast<camera::Id>(id)); });

    cam["set_param"] = [&manager](const std::string& key, double value) {
        return manager.set_param_active(key, value);
    };

    cam["list"] = [&manager, L]() {
        sol::state_view lua(L);
        sol::table t = lua.create_table();
        const std::vector<std::string> names = manager.names();
        for (std::size_t i = 0; i < names.size(); ++i) {
            t[i + 1] = names[i];
        }
        return t;
    };

    // 占位（P0 不实现，P1 补齐）：固定返回 false，保持调用不报错。
    cam["shake"] = [](sol::variadic_args) { return false; };
    cam["set_follow"] = [](sol::variadic_args) { return false; };
}
```

- `register_all` 保持只注册 `api.log.*` + `api.util.*`（无状态）；`api.camera.*` 因需注入 `camera::Manager&`，与 `api.event.*` 一样在调用方单独注册。
- 未注册 `api.camera` 时，Lua 调 `api.camera.*` 报错不崩溃、`do_file` 返回 `false`（沿用既有约定）。

### 4. 最小运行接线（`app/model_viewer_game.cpp`）

- `ModelViewerGame` 新增成员 `camera::Manager cameraManager_;` 与 `lua_engine::Engine lua_;`。
- `init()`：
  1. 创建若干 isometric 相机（如 `"default"` 距离 15、`"near"` 距离 8、`"far"` 距离 25），`set_active("default")`。
  2. `api::register_all(lua_)` + `api::register_camera(lua_.raw_state(), cameraManager_)`。
  3. `lua_.do_file(asset_path::resolve("lua/demo_camera.lua"))` 加载演示脚本。
- `render()`：渲染相机来源改为「活动相机 → `to_camera3d`」，即 `BeginMode3D(camera::to_camera3d(*cameraManager_.active_params()))`，替换原先直接使用的 `camera_`。
- **现有环绕/手动调试控制回归**：将原 `camera_`（`Camera3D`）保留为调试控制的工作副本，环绕/手动控制在副本上执行后回写到活动相机参数（经 `set_param` 分量键或直接经 `active_params()` 写回），保证现有交互不回归、同时 Lua 也能驱动同一活动相机。默认视角 / 预设视角按钮改为写回活动相机参数。
- 演示脚本 `lua/demo_camera.lua`：启动时 `switch` + `set_param` 演示（改 FOV/距离），配合日志输出，供运行验证观察切换与参数生效。

> 注：P0-08 只做「相机由 Lua 驱动」的最小接线；`config` + `event` + `ecs` + `camera` 的全链路串联留给 P0-09。

## 确认结果 (2026-10-01)

1. **raylib 依赖隔离**：接受「纯逻辑核心 + 独立 raylib 适配头」的隔离方式（§0-1 / §2），对齐 ADR-9 / ADR-14。
2. **set_param 键集与 isometric 联动**：接受 §0-3 / §0-4 / §1 的键集合（`fov`/`distance` 核心 + 分量键）与 isometric 位置联动语义。
3. **运行接线方式**：接受 §4「渲染相机由活动相机驱动 + 现有调试控制回写活动相机参数」的方式（对现有 `camera_` 控制代码做小幅重构）。
4. **`get_active_id` 扩展**：接受额外暴露 `api.camera.get_active_id`（满足名称/id 双标识需求）。
