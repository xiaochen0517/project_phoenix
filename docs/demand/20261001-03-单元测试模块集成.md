## 需求背景

P0 骨架阶段要求「各层有单元测试覆盖」，但当前项目尚无测试框架：`core/` 只有一个 `project_phoenix` 可执行目标，所有验证都依赖「运行程序 + 人工观察日志 / 画面」。为把可自动回归的纯逻辑部分（脚本引擎、日志等）纳入自动化，需要先接入测试框架并搭建可被 `ctest` 调度的测试目标。

选型结论（`docs/roadmap/P0骨架需求拆分.md` §1）已确定使用 **Catch2**（若后续偏好更轻量可换 doctest，不影响本需求以外的决策）。

## 需求目标

1. 在 CMake 中接入 Catch2，新增独立的测试可执行目标 `project_phoenix_tests`，并接入 `ctest`。
2. 将基础、可直接自动测试的模块（`script/lua_runner`、`script/sol2_bridge`、`log/app_log`）纳入单元测试，保证无头（无窗口 / 无 GL 上下文）可跑。

## 设计方案

### 1. 依赖接入（vcpkg + CMake）

- `vcpkg.json`：新增 `"catch2"`（版本由 builtin-baseline 固定）。
- 顶层 `CMakeLists.txt`：
  - 新增 `find_package(Catch2 CONFIG REQUIRED)`。
  - 新增 `enable_testing()`（或 `include(CTest)`），启用 `ctest` 调度。
- `core/CMakeLists.txt`：
  - 新增测试目标 `project_phoenix_tests`，复用可测业务源文件（`log/app_log.cpp`、`script/lua_runner.cpp`、`script/sol2_bridge.cpp`），链接 `Catch2::Catch2WithMain`（提供 `main`）+ `spdlog::spdlog` + `${LUAJIT_LIBRARY}` + `sol2::sol2`。
  - `add_test(NAME ... COMMAND project_phoenix_tests)` 注册到 ctest。

> 说明：测试目标**不**链接 raylib / rlimgui / `model_loader`（后者需 GL 上下文与模型资产，属运行验证范畴，见 roadmap 的「验证双轨」）。无头测试仅覆盖纯逻辑模块，保证命令行 / CI 可直接运行。

### 2. 测试用例

新建 `core/tests/`，按模块拆分测试文件：

| 文件 | 覆盖模块 | 用例要点 |
|---|---|---|
| `test_lua_runner.cpp` | `lua_runner::eval_string` | 表达式求值返回正确值、多行脚本、错误脚本返回 `error: ` 前缀、返回 nil/空字符串 |
| `test_sol2_bridge.cpp` | `sol2_bridge::self_test` | 自检报告包含 `6 passed, 0 failed`（即 6 项全 PASS） |
| `test_app_log.cpp` | `app_log` | 冒烟测试：`init()` + 各级别日志调用不崩溃 |

### 3. 验证方式

- `cmake --preset msvc-debug` + `cmake --build --preset msvc-debug` 构建通过。
- `ctest --preset msvc-debug`（或 `ctest --test-dir build/msvc-debug`）运行测试，全部 PASS。
