# P0 骨架需求拆分

> 版本: v0.5 (2026-10-01, P0-01 三项集成均已完成)
>
> 本文档将《项目规划文档》中的 **P0 骨架** 阶段拆分为可独立实现、可独立测试的子需求。
> 每个子需求实现后可立即测试验证，通过后再进入下一项。
>
> 实现顺序、依赖关系与验收标准以本文档为准；具体实现细节在编码前如需再确认，会单独询问。

---

## 0. 概述与目标

- **P0 目标**：跑通「C++ / Lua / 配置」三层边界，形成可复用的骨架。
- **总验收标准**：Lua 能读配置、调用 API、收发事件；程序以固定 tick 推进；各层有单元测试覆盖。
- **验证双轨**：
  - 纯逻辑层（ECS / 事件 / 配置 / JSON / Lua 绑定）→ **Catch2 单元测试**自动回归。
  - 表现层（相机、画面、主循环）→ **运行程序手动验证**（沿用 `AGENTS.md` 约定）。

## 1. 选型结论（已定案）

| 项 | 选择 | 备注 |
|---|---|---|
| JSON 库 | nlohmann/json | header-only，vcpkg 可用 |
| Lua 绑定 | sol2 | header-only（v3.5.0），支持 LuaJIT(5.1)；vcpkg 提供 target `sol2::sol2` |
| ECS | entt | header-only，sparse-set |
| Lua 运行时 | **LuaJIT** | vcpkg `luajit`（2.1 线），Lua 5.1 API + JIT |
| 测试框架 | Catch2 | 若偏好更轻量可换 doctest，不影响其他决策 |
| 热重载范围 | 模块加载 + 基础重载 | 完整热重载（函数级/自动监听）留到 P7 |

> **sol2 + LuaJIT 组合已实测通过，确定为最终方案**（见需求 `20261001-01 LuaJIT功能测试`、`20261001-02 LuaJIT结合sol2测试`，均已完成）。实测结论：
> - vcpkg `luajit` 端口：库名 `lua51`、头文件位于 `include/luajit/` 子目录、**不提供标准 CMake target**（仅 pkg-config），需手动 `find_path` / `find_library` 定位。
> - sol2 走 vcpkg `sol2` 端口（v3.5.0），提供 CMake target `sol2::sol2`，经 `find_package(sol2 CONFIG REQUIRED)` 引入，与 LuaJIT 静态链接无冲突。
> - sol2 绑定自检 6 项全部 PASS（JIT 可用 / C++→Lua / Lua→C++ 多返回 / usertype / 容器 / 异常）。

## 2. 依赖与构建变更（P0-01）

### 目标
引入并验证所有新依赖，搭建单元测试目标，为后续所有子需求打底。

### 涉及
`vcpkg.json`、顶层 `CMakeLists.txt`、`core/CMakeLists.txt`、`CMakePresets.json`。

### 子任务拆解

#### 2.1 LuaJIT 集成（已完成）
- 状态：已完成（需求 `20261001-01`）。
- 内容：`vcpkg.json` 引入 `luajit`；顶层 `CMakeLists.txt` 用 `find_path` / `find_library` 定位（库名 `lua51`、头目录 `include/luajit`），`core/CMakeLists.txt` 链接 `${LUAJIT_LIBRARY}`。
- 备注：vcpkg `luajit` 端口不提供标准 CMake target（仅 pkg-config），故手动定位。

#### 2.2 Sol2 集成（已完成）
- 状态：已完成（需求 `20261001-02`）。
- 内容：`vcpkg.json` 引入 `sol2`（v3.5.0）；顶层 `CMakeLists.txt` `find_package(sol2 CONFIG)`；`core/CMakeLists.txt` 链接 `sol2::sol2`。
- 备注：sol2 为 header-only，经 target `sol2::sol2` 引入，与 LuaJIT 静态链接无冲突。

#### 2.3 单元测试集成（已完成）
- 状态：已完成（需求 `20261001-03 单元测试模块集成`）。
- 内容：
  1. `vcpkg.json` 引入 `catch2`（测试框架，选型见 §1）。
  2. CMake 接入：`find_package(Catch2 CONFIG)` + `enable_testing()` / `include(CTest)`；新增测试目标 `project_phoenix_tests`，链接 `Catch2::Catch2WithMain` + 可测业务模块（`lua_runner` / `sol2_bridge` / `app_log`），接入 `ctest`。
  3. 将基础可直接自动测试的部分（`lua_runner::eval_string`、`sol2_bridge::self_test`、`app_log` 冒烟）纳入单元测试。
- 备注：测试目标不链接 raylib / rlimgui / `model_loader`（需 GL 上下文与资产，属运行验证范畴），保持无头可跑。

### 实现要点（汇总）
0. **前置验证（已完成）**：sol2 + LuaJIT 组合已在需求 `20261001-01` / `20261001-02` 实测通过（sol2 自检 6 项全部 PASS，VS18/MSVC 编译链接运行无冲突），已落地接入。

### 验收标准

## 3. 子需求拆分

### P0-02 应用框架与主循环（`app/`）

- **目标**：拆分 `main.cpp`，引入 App 生命周期，落地固定 tick 累加器。
- **涉及**：`app/`（新增）、`main.cpp`（拆分）。
- **实现要点**：
  1. 定义 `App`/`Game` 类，生命周期：`init()` → 主循环 → `shutdown()`。
  2. 固定 tick：`FIXED_DT = 1/30`，用累加器驱动 `update(FIXED_DT)`，渲染侧 `render(alpha)` 接收插值系数 `alpha ∈ [0,1)`。
  3. `update` 固定步长调用；渲染插值在 `render` 内完成。
  4. 将现有 `main.cpp` 的模型查看器功能迁移进 `app/`，作为 P0 阶段的运行载体（不新增业务）。
- **验收标准**（运行验证）：
  - 程序正常启动/退出。
  - 日志可观察到逻辑以 30Hz 推进（累计 `update` 次数 ≈ 运行秒数 × 30）。
- **依赖**：P0-01。

---

### P0-03 Lua 引擎持久化（`script/`）

- **目标**：用 sol2 封装持久 `lua_State`，支持模块加载与基础重载，替换现有一次性 `eval_string`。
- **涉及**：`script/`（重构 `lua_runner`）。
- **实现要点**：
  1. 持久持有 `lua_State`（sol2 下为 `sol::state`），不再每次新建/销毁。
  2. `openlibs`；本阶段先开放标准库，安全裁剪后续再做。
  3. 提供 `do_file(path)` / `call_function(name, args...)` / `reload(path)`（手动触发重载）。
  4. 错误经 `app_log` 输出，不静默吞掉。
- **验收标准**（单元测试）：
  - 加载 Lua 文件 → 调用函数返回正确值。
  - 修改脚本文件 → `reload` 后取到新返回值。
- **依赖**：P0-01。

---

### P0-04 API 绑定框架（`script/`）

- **目标**：建立 `api.*` 注册表结构，用绑定库绑定 C++ 函数供 Lua 调用。
- **涉及**：`script/`（API 注册）。
- **实现要点**：
  1. 约定注册结构：各业务模块提供 `register(...)`（签名随绑定库而定），统一挂到 `api.<module>.<func>` 命名空间。
  2. 命名规范：`api.log.*`、`api.event.*`、`api.camera.*`、`api.ecs.*` 等。
  3. 提供基础验证 API（如 `api.log.info`），打通 C++→Lua 调用链。
- **验收标准**（单元测试）：
  - Lua 调用 `api.log.info(...)` 输出日志。
  - Lua 调用 API 取到 C++ 返回值。
- **依赖**：P0-03。

---

### P0-05 事件总线（`event/`）

- **目标**：实现 C++ 事件产生/订阅/分发，Lua 可注册事件处理函数。
- **涉及**：`event/`（新增）、`script/`。
- **实现要点**：
  1. 事件类型 + 订阅表；本阶段采用**同步分发**（延迟队列后续按需引入）。
  2. C++ `emit(event)` 分发到订阅者。
  3. Lua 注册处理：`api.event.on(name, func)`。
  4. 事件载荷用基础类型（string / number / 后续扩展）经绑定库转换。
- **验收标准**（单元测试）：
  - C++ `emit` → Lua handler 被调用。
  - Lua 内 `emit` → C++ 订阅者收到。
- **依赖**：P0-04。

---

### P0-06 配置系统（`config/`）

- **目标**：用 nlohmann/json 实现 JSON 加载与访问接口。
- **涉及**：`config/`（新增）。
- **实现要点**：
  1. JSON 文件加载与错误报告。
  2. 读取接口：按 key 读取、带默认值读取、嵌套访问。
  3. 基础校验（可选字段 + 必填字段）。
  4. 路径解析复用现有 `resolveAssetPath` 思路。
- **验收标准**（单元测试）：
  - 加载 JSON、读取字段正确。
  - 缺失字段返回默认值；非法 JSON 报错不崩溃。
- **依赖**：P0-01。

---

### P0-07 ECS 骨架（`ecs/`）

- **目标**：用 entt 封装 entity/component/system。
- **涉及**：`ecs/`（新增）。
- **实现要点**：
  1. Registry 封装：entity 创建 / 销毁。
  2. component 定义、attach / get。
  3. `view` 查询与基础遍历。
  4. system 骨架：约定 system 函数签名 + 统一更新循环（供后续 Lua 规则接入）。
- **验收标准**（单元测试）：
  - 创建实体 → 加组件 → view 遍历得到正确实体数。
  - 销毁实体后组件被正确清理。
- **依赖**：P0-01。

---

### P0-08 相机系统骨架（`camera/`）

- **目标**：建立相机模块 + `api.camera.*` 绑定 + 一个最小相机类型作为验证载体。
- **涉及**：`camera/`（新增）、`script/`。
- **实现要点**：
  1. 多相机实例管理（实例列表 + 活动相机）。
  2. `api.camera.*` 绑定：`get_active` / `switch` / `set_param` / `list`（`shake` / `set_follow` 先占位）。
  3. 实现一个最小 isometric 相机作为验证载体；**完整跟随/平滑/操控放 P1**。
  4. 复用 raylib `Camera3D` 概念。
- **验收标准**（单元测试 + 运行验证）：
  - Lua 配置相机、`switch` 切换、`set_param` 改 FOV/距离后生效。
- **依赖**：P0-02、P0-04。

---

### P0-09 端到端集成验证

- **目标**：串起各层，验证三层边界闭环。
- **涉及**：`app/` + 所有模块。
- **实现要点**：
  1. 一个 demo 场景跑通链路：加载 JSON 配置 → Lua 初始化/订阅事件 → ECS 创建玩家实体 → 触发事件 → Lua 处理 → 调 `api.camera.switch`。
  2. 日志 + 画面均可观察各层已打通。
- **验收标准**（运行验证）：
  - 运行 demo，日志显示完整链路；画面显示相机切换效果。
- **依赖**：P0-02 ~ P0-08。

## 4. 实现顺序与依赖

```text
P0-01 依赖与构建
   ├─> P0-02 应用框架与主循环 (app/)
   ├─> P0-03 Lua 引擎持久化 (script/)
   │       └─> P0-04 API 绑定框架 (script/)
   │               └─> P0-05 事件总线 (event/)
   ├─> P0-06 配置系统 (config/)
   ├─> P0-07 ECS 骨架 (ecs/)
   └─> P0-08 相机系统骨架 (camera/)  [依赖 P0-02 + P0-04]
                     └─> P0-09 端到端集成验证
```

推荐实现顺序：**01 → 02 → 03 → 04 → 05 → 06 → 07 → 08 → 09**。
（06 / 07 与 03~05 无强依赖，可并行，但按顺序推进更易控。）

## 5. 风险与待确认

| 风险 | 说明 | 应对 |
|---|---|---|
| sol2 + LuaJIT 组合（已实测通过） | sol2 自检 6 项全部 PASS，VS18 编译链接运行无冲突 | 无需额外验证；后续绑定留意踩坑点（jit 用无参 `open_libraries()`、容器参数按值传） |
| vcpkg luajit 无标准 CMake target | 库名 `lua51`、头目录 `include/luajit`、仅 pkg-config | 顶层 `CMakeLists.txt` 已用 find_path/find_library 定位 |
| 事件同步分发 vs 延迟队列 | 本阶段选同步，复杂度低 | 后续需要时引入延迟队列 |

- P0-07：system 骨架是否在 P0 就预留「Lua 规则接入」接口，还是 P0 只做纯 C++ ECS。
