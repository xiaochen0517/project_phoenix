## 0. 概述与目标

- **P0 目标**：跑通「C++ / Lua / 配置」三层边界，形成可复用的骨架。
- **总验收标准**：C++ 读配置并驱动初始化、Lua 调用 API 与收发事件；程序以固定 tick 推进；各层有单元测试覆盖。
- **验证双轨**：
  - 纯逻辑层（ECS / 事件 / 配置 / JSON / Lua 绑定）→ **Catch2 单元测试**自动回归。
  - 表现层（相机、画面、主循环）→ **运行程序手动验证**（沿用 `AGENTS.md` 约定）。

## 1. 选型结论（已定案）

| 项 | 选择 | 备注 |
|---|---|---|
| JSON 库 | nlohmann/json | header-only，vcpkg 可用 |
| Lua 绑定 | sol2 | header-only（v3.5.0），支持 LuaJIT(5.1)；vcpkg 提供 target `sol2::sol2` |
| ECS | entt | header-only，sparse-set |
| Lua 运行时 | **LuaJIT** | vcpkg `luajit`（2.1 线），Lua 5.1 API + JIT |
| 测试框架 | Catch2 | 若偏好更轻量可换 doctest，不影响其他决策 |
| 热重载范围 | 模块加载 + 基础重载 | 完整热重载（函数级/自动监听）留到 P7 |

> **sol2 + LuaJIT 组合已实测通过，确定为最终方案**（见需求 `20261001-01 LuaJIT功能测试`、`20261001-02 LuaJIT结合sol2测试`，均已完成）。实测结论：
> - vcpkg `luajit` 端口：库名 `lua51`、头文件位于 `include/luajit/` 子目录、**不提供标准 CMake target**（仅 pkg-config），需手动 `find_path` / `find_library` 定位。
> - sol2 走 vcpkg `sol2` 端口（v3.5.0），提供 CMake target `sol2::sol2`，经 `find_package(sol2 CONFIG REQUIRED)` 引入，与 LuaJIT 静态链接无冲突。
> - sol2 绑定自检 6 项全部 PASS（JIT 可用 / C++→Lua / Lua→C++ 多返回 / usertype / 容器 / 异常）。

## 3. 子需求拆分

### P0-02 应用框架与主循环（`app/`）（已完成）

- **状态**：已完成（需求 `20261001-04 应用框架与主循环`）。
- **目标**：拆分 `main.cpp`，引入 App 生命周期，落地固定 tick 累加器。
- **涉及**：`app/`（新增）、`main.cpp`（拆分）、`util/asset_path`（新增，`resolveAssetPath` 抽自 `main.cpp`）。
- **实现要点**（已落地）：
  1. 三层结构：`app::App`（外壳：窗口/ImGui/主循环） + `app::Game`（业务抽象接口） + `app::ModelViewerGame`（迁移现有模型查看器）。
  2. 固定 tick：`kFixedDt = 1/30`，`App::run` 用累加器驱动 `update(fixedDt)`；帧时间上限 0.25s 防死亡螺旋；渲染侧 `render(alpha)` 接收 `alpha ∈ [0,1)`。
  3. `update` 固定步长调用（一次或多次追帧）；`render` 每帧调用一次；`alpha = accumulator / kFixedDt`。
  4. 模型查看器迁移进 `ModelViewerGame`；动画推进保留在 `render` 每帧（平滑），`update(fixedDt)` 仅累计 tick 验证 30Hz。
  5. `resolveAssetPath` 抽为独立 `util/asset_path`，供后续 `config/` 等复用。
- **验收标准**（运行验证，已通过）：
  - 程序正常启动/退出；窗口与模型查看器交互和迁移前一致。
  - 日志每秒输出 `fixed tick`，`rate ≈ 30`，逻辑以 30Hz 推进（累计 `update` 次数 ≈ 运行秒数 × 30）。
  - 构建通过；`ctest` 7 项全 PASS（无回归）。
- **依赖**：P0-01。

### P0-03 Lua 引擎持久化（`script/`）（已完成）

- **状态**：已完成（需求 `20261001-05 Lua引擎持久化`）。
- **目标**：用 sol2 封装持久 `lua_State`，支持模块加载与基础重载，替换现有一次性 `eval_string`。
- **涉及**：`script/`（重构 `lua_runner` → `lua_engine`，删除 `sol2_bridge`）、根目录 `lua/`（新增，脚本统一存放）。
- **实现要点**（已落地）：
  1. 合并 `lua_runner` + `sol2_bridge` 为单一 `lua_engine::Engine`（namespace `lua_engine`，pimpl 持有 `sol::state`，公开头不暴露 sol2 / ADR-5）。
  2. 无参 `open_libraries()`（等价 `luaL_openlibs`）以注册 `jit` 全局量；容器参数按值传（沿用已实测踩坑结论）。
  3. 接口：`do_file(path)` / `reload(path)`（P0 阶段与 `do_file` 语义等价，函数级热重载留 P7）/ `call_function(name)`（P0 仅无参、返回 `Value`：nil/bool/number/string 四类）。
  4. 删除旧一次性 `eval_string`、`sol2_bridge::self_test` 及对应测试、运行期启动自检与 ImGui「LuaJIT + sol2」面板。
  5. 错误经 `app_log` 输出并返回 `false`，不静默吞掉。
- **验收标准**（单元测试，已通过）：
  - `do_file` 加载 `lua/` 脚本 → `call_function` 返回正确值。
  - `reload` 动态改写脚本 → 取到新返回值。
  - 非法/不存在脚本返回 `false` 不崩溃。
  - `ctest` 5 用例全 PASS（`lua_engine` 4 + `app_log` 1）；运行侧无回归。
- **依赖**：P0-01。

### P0-04 API 绑定框架（`script/`）（已完成）

- **状态**：已完成（需求 `20261001-06 API绑定框架`）。
- **目标**：建立 `api.*` 注册表结构，用绑定库绑定 C++ 函数供 Lua 调用。
- **涉及**：`script/api_registry.{h,cpp}`（新增）、`script/lua_engine`（新增 `raw_state()` 访问器）。
- **实现要点**（已落地）：
  1. 注册约定：每个业务模块一个 `register_<module>(lua_State *)`（签名统一裸 `lua_State*`，sol2 仅在 `.cpp`），汇总入口 `api::register_all(lua_State *)`。
  2. 命名规范：`api.<module>.<func>`，sol2 嵌套 `sol::table`（`get_or_create` 幂等创建）；已有 `api.log.*`、`api.util.add`。
  3. `Engine::raw_state()` 暴露裸 `lua_State*`，绑定层用 `sol::state_view` 包装（不接管内存，生命周期仍由 `Engine` 负责）。
  4. 基础验证 API：`api.log.*`（绑定 `app_log::*`）打通 C++→Lua 调用链；`api.util.add(a, b)` 打通 C++ 返回值回传 Lua。
- **验收标准**（单元测试，已通过）：
  - Lua 调 `api.log.info(...)` 输出日志（spdlog 捕获断言）。
  - Lua 调 `api.util.add(2, 3)` 取到返回值 `5.0`。
  - 未注册模块（如 `api.event`）报错不崩溃，`do_file` 返回 `false`。
  - `ctest` 8 用例全 PASS（`api_bindings` 3 + `lua_engine` 4 + `app_log` 1）；`app/` 未改动，运行侧无回归。
- **依赖**：P0-03。

### P0-05 事件总线（`event/`）（已完成）

- **状态**：已完成（需求 `20261001-07 事件总线`）。
- **目标**：实现 C++ 事件产生/订阅/分发，Lua 可注册事件处理函数。
- **涉及**：`event/`（新增）、`script/`。
- **实现要点**（已落地）：
  1. `event::Value`（nil/bool/number/string 四类基础类型）+ `event::Bus`（`on`/`off`/`emit`，纯 C++ 不依赖 sol2）。
  2. 本阶段采用**同步分发**；`on` 返回订阅 id，`off(name, id)` 精确移除。
  3. Lua 绑定 `api.event.*`：`on(name, func)` 支持同名多 handler、`off(name)` 按名移除、`emit(name, payload?)`；经 `register_event(lua_State*, event::Bus&)` 注入 bus。
  4. 事件载荷用四类基础类型经绑定层转换（number/string/bool/nil）。
- **验收标准**（单元测试，已通过）：
  - C++ `emit` → Lua handler 被调用。
  - Lua 内 `emit` → C++ 订阅者收到。
  - `ctest` 13 用例全 PASS（`event_bus` 5 + `api_bindings` 3 + `lua_engine` 4 + `app_log` 1）；运行侧无回归。
- **依赖**：P0-04。
