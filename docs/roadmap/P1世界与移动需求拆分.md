## 0. 概述与目标

- **P1 目标**：跑通「能走的地图」——等距相机落地、chunk 地图、tile、角色移动、碰撞、相机跟随。
- **总验收标准**：角色在 tile 地图上移动（W/A/S/D 方向移动 + 碰撞阻挡）、相机正确跟随角色、地图分块可查询。
- **验证双轨**：
  - 纯逻辑层（输入映射 / 地图加载与查询 / 移动与碰撞判定 / 相机跟随数学 / api.ecs 绑定）→ **Catch2 单元测试**自动回归。
  - 表现层（tile 渲染、角色移动观感、相机跟随观感）→ **运行程序手动验证**（沿用 `AGENTS.md` 约定）。

## 1. 已定案决策（P1 开工前确定）

| 项 | 决策 | 备注 |
|---|---|---|
| 相机类型 | 支持两类：透视 isometric + 正交 isometric，配置用属性标记类型 | `Type` 扩展；Lua 配置 `type = "isometric" \| "isometric_ortho"` |
| 相机配置来源 | **Lua 表** | 相机是「规则」，P1 范围已定「Lua 配置加载」 |
| 地图规模 | 64×64，chunk 16×16（4×4 chunk） | MVP 起步值 |
| tile 渲染/坐标 | 3D 世界，`x/z` 水平面移动、`y` 为高度 | raylib 3D 场景 |
| 移动控制 | 方向事件 + 按键绑定 | `input/` 产生 `move_up/down/left/right`，绑定 W/A/S/D |
| 碰撞 | tile 网格 walkability | 含边墙 + 整格阻塞 |
| 墙面表示 | **边墙为主 + 整格阻塞补充** | 边墙存独立集合 `{cell, side}`；柱子/巨石等用整格阻塞 tile |
| 层级 | 引入 `level`，MVP 2 层（ground + upper） | 楼梯 tile 触发层级切换 |
| 地图存储 | JSON：`tile_defs` + 每层 `tiles` id 数组 + `walls` 边墙集合 | 按 chunk 逻辑切分 |
| 移动逻辑归属 | C++ 热路径（ECS system）+ **引入 `api.ecs`** | Lua 可读/写实体位置与层 |
| 输入抽象 | 落地最小 `input/` 模块 | 隔离 raylib 输入 API |

### 1.1 坐标与方向约定

3D 世界坐标，`y` 为高度（向上），移动发生在 `x/z` 水平面。约定：

- 地图北 = `-z`，东 = `+x`，南 = `+z`，西 = `-x`。
- 等距视角下屏幕「上」= 地图西北（地图正上 = 北），因此方向映射：

| 输入动作 | 按键 | 地图方向 | x/z 单位向量 |
|---|---|---|---|
| `move_up` | W | 西北 | `normalize(-1, 0, -1)` |
| `move_down` | S | 东南 | `normalize(+1, 0, +1)` |
| `move_left` | A | 西南 | `normalize(-1, 0, +1)` |
| `move_right` | D | 东北 | `normalize(+1, 0, -1)` |

> 具体向量正负号在实现阶段与相机实际朝向做一次对齐校验；「北 = 屏幕上、W = 西北」的语义约定固定不变。

## 3. 子需求拆分

### P1-01 输入抽象（`input/`）

- **状态**：已完成（需求 `20261002-02 输入抽象`）。
- **目标**：落地最小输入模块，把 raylib 键盘采样封装为「动作」层，隔离输入 API。
- **涉及**：`input/`（新增）、`core/CMakeLists.txt`。
- **实现要点**：
  1. `namespace input`，纯逻辑核心与 raylib 读取分离（对齐 ADR-5 / ADR-9：核心可无头单测，raylib 采样在运行侧适配层）。
  2. 动作定义：`move_up / move_down / move_left / move_right`（P1 只做 4 向移动；8 向斜移留给后续，动作表预留扩展）。
  3. 按键绑定：动作 → 按键的映射可配置（默认 W/A/S/D），提供 `bind(action, key)` / `unbind` / `query`。
  4. 采样：每固定 tick 开头采样一次（对齐规划文档 §4.2 `sample_input()`），输出「本 tick 动作状态」（按下/释放/持续）。
  5. 动作 → 移动方向向量：提供纯函数 `action_to_dir(action)`，按 §1.1 约定返回 x/z 单位向量（可单测）。
- **验收标准**（单元测试 + 运行验证）：
  - 绑定/解绑/查询动作映射正确（单测）。
  - `action_to_dir` 四方向向量符合 §1.1（单测）。
  - 运行侧按住 W 可观察到 `move_up` 动作持续触发。
- **依赖**：无。

### P1-02 世界与地图（`world/`）

- **状态**：已完成（需求 `20261002-03 世界与地图`）。
- **目标**：实现 chunk 分块 tile 地图：tile 定义、边墙、整格阻塞、level 多层、JSON 加载、坐标换算与 walkability 查询。
- **涉及**：`world/`（新增）、根目录 `config/`（地图 JSON 资产）、`core/CMakeLists.txt`。
- **实现要点**：
  1. **tile 定义表**（`tile_defs`）：`id / name / walkable / height / color / stairs?`，从 JSON 载入，地图内只存 id。
  2. **多层结构**：`levels[]`，每层独立 64×64 tile 平面 + 边墙集合；MVP 2 层（ground + upper），数据结构支持任意层。
  3. **边墙集合**：每面墙用 `{cell(x,z), side(n/e/s/w)}` 唯一表示（不做双向冗余），与整格阻塞 tile 共享 walkability 判定。
  4. **chunk 分块**：64×64 按 16×16 切成 4×4 chunk，逻辑上分块查询（存储上整体存一份 JSON，加载后切块）。
  5. **坐标换算**：`world → tile`（`tile = floor(world / tile_size)`）、`tile → chunk`、`tile → world`（tile 中心）等纯函数（可单测）。
  6. **查询接口**：`is_walkable(tile)` / `has_wall(tile, side)` / `tile_def(tile)` / `stairs(tile)`；JSON 加载失败经 `app_log` 报错。
  7. `world/` 纯逻辑不依赖 raylib / sol2（可无头测试）；路径解析由调用方用 `asset_path::resolve` 完成（对齐 ADR-14）。
- **验收标准**（单元测试）：
  - 加载示例地图 JSON，读取 tile 定义 / 层 / 边墙正确。
  - 坐标换算（world↔tile↔chunk）正确，含负数与边界。
  - `is_walkable` / `has_wall` / `stairs` 查询结果正确。
  - 非法 JSON / 越界查询报错不崩溃。
- **依赖**：无。

### P1-03 移动与碰撞（`ecs/` + `world/`）

- **状态**：已完成（需求 `20261002-04 移动与碰撞`）。
- **目标**：在 ECS 上落地移动 system：输入方向驱动角色移动，经 tile walkability + 边墙碰撞，支持楼梯层级切换。
- **涉及**：`ecs/`（组件 schema）、`world/`（碰撞查询）、`input/`（动作方向）、`scene/main_game/`（接入）。
- **实现要点**：
  1. **组件正式化**：把 demo 局部的 `Position` 提升为正式 ECS 组件（含 `x/y/z`），新增 `Mover`（`speed` + `level`）组件；`level` 记录角色当前层。
  2. **移动 system**（C++ 热路径）：每 tick 读 `input` 动作 → `action_to_dir` 合成方向 → `next = pos + dir * speed * dt` → 碰撞判定后写回位置。
  3. **碰撞判定**（纯函数，可单测）：`next` 映射到 tile → ① 目标 tile `walkable`；② 跨格时查边墙；③ 命中 `stairs` 则触发层级切换而非继续移动；任一阻挡则该方向不移动。
  4. **楼梯层级切换**：踩到 `stairs_up/down` tile → 切换 `Mover.level` 并把角色放到目标层对应位置。
  5. 移动与碰撞的数学部分（方向合成、walkability 判定、层级切换）保持纯逻辑可单测，与 raylib 无关。
- **验收标准**（单元测试 + 运行验证）：
  - 方向合成、walkability 阻挡、边墙阻挡、楼梯切换的纯逻辑判定单测通过。
  - 运行侧角色按 W/A/S/D 在地图上移动，撞墙/撞不可走 tile 被阻挡，踩楼梯切换层级。
- **依赖**：P1-01、P1-02。
- **备注**：移动与碰撞（纯逻辑 + 接入）已完成并通过验证；**tile / 玩家模型 / 相机渲染观感与碰撞/墙高存在问题，另立拆分项「渲染遮挡与移动碰撞」**（需求 `20261002-05`，**已完成**：遮挡判定 `visibility/` 模块 + 建筑内标志 + 垂直缩放 3m 墙高 + 墙面 2D 平面 + 边墙接缝碰撞 + 门洞）。

### P1-04 等距相机落地（`camera/`）

- **状态**：已完成（需求 `20261003-01 等距相机落地`）。
- **目标**：扩展相机类型（透视 + 正交 isometric），JSON 配置加载，实现跟随与平滑，实装 `api.camera.set_follow`。
- **涉及**：`camera/`（`camera.h/.cpp`、`camera_config.h/.cpp`、`camera_raylib.h`）、`script/`（`api.camera`）、`config/`（`camera.json`）、`scene/main_game/world_scene`。
- **实现要点**：
  1. `Type` 扩展：`Isometric`（透视）+ `IsometricOrtho`（正交），`type` 迁入 `Params`（单一事实来源，`create(name, params)` 签名简化）；`apply_isometric` 对两类都推导位置，创建/`set_type` 按类型写默认 `projection`。
  2. **配置加载（JSON）**：相机类型/参数/跟随平滑用 `config/camera.json` 定义（`type = "isometric" | "isometric_ortho"`、`distance/fovy/follow{smoothing}`），`camera::load_config` 解析并创建相机实例；失败兜底内置默认。
  3. **跟随**：`set_follow(entity, smoothing)` 实装——`follow_hard` 每 tick 读取目标实体 `Position`（场景侧从 `ecs` 读入）target 直写 + `apply_isometric` 重算 position（**实时跟随，用户 2026-10-03 运行验证确认取消平滑**）；`follow_tick` 指数平滑能力保留在核心层（帧率无关、纯函数可单测）供后续镜头特效复用。
  4. `api.camera` 补充：`set_follow` 真实现 + `clear_follow` + `get_type` / `set_type`（`shake` 继续占位）。
  5. raylib 适配层 `to_camera3d` 支持正交投影（`projection` 直拷，0/1 与 raylib 枚举对齐）。
- **验收标准**（单元测试 + 运行验证）：
  - `apply_isometric` 对透视/正交两类推导正确；`follow_hard` 直写与 `follow_tick` 平滑数学（收敛/帧率无关/snap）可单测。
  - 运行侧 JSON 配置两类相机、ImGui/Lua 切换生效；角色移动时相机实时跟随、无滞后。
- **依赖**：P1-03（跟随需要目标实体位置）。
- **备注**：**配置来源偏离原「Lua 表」定案**——用户 2026-10-03 确认：相机配置走 JSON（`config/camera.json`，对齐既有 `config/` 体系），Lua 侧只承载逻辑类功能（切换/参数修改），见需求 `20261003-01` §0-2。

## 5. 风险与待确认

| 风险 | 说明 | 应对 |
|---|---|---|
| 等距方向向量与相机朝向未对齐 | §1.1 的 x/z 向量符号需与相机实际朝向一致 | 实现 P1-01 时先做一次「W = 西北 = 屏幕上」的对齐校验，再固化常量 |
| 边墙集合的「边方向」命名歧义 | `side: n/e/s/w` 需全项目统一（北边 = 该格朝向 -z 的一侧） | 在 `world/` 文档注释中固定约定，单测覆盖 |
| 高速移动穿透薄墙 | 单 tick 步长可能跨过边墙 | P1 MVP 速度慢、单次判定即可；后续如需再加子步进 |
| 正交 isometric 的缩放/距离适配 | 正交投影下 `distance/fov` 语义与透视不同 | 两类相机参数分开处理（正交 fovy = 垂直视野世界单位，distance 仍推导位置），默认值见 `config/camera.json`，运行侧验证观感后固化 |
| 层级切换与相机跟随的衔接 | 切层瞬间相机 target 跳变可能造成视觉跳变 | 相机跟随按层切换目标，smoothing 平滑过渡，运行侧验证 |

### 后续进入各子需求实现前的确认点

- P1-01：动作表是否只做 4 向（`move_up/down/left/right`），斜向（NW/NE/SW/SE 8 向）是否 P1 一并支持。→ **已确认：P1 仅 4 向，斜向预留扩展**（见需求 `20261002-02`）。
- P1-02：`tile_defs` 字段集（是否含纹理/高度/额外属性）与地图 JSON 最终 schema 在编码前最终确认。→ **已确认**：数值 id + 纹理字段（`texture`，P1 定形不加载），`tile_defs` 对象数组 + `levels[]`（见需求 `20261002-03` §4）。
- P1-04：相机配置表结构与 `set_follow` 参数签名。→ **已确认**：配置走 JSON（`config/camera.json`：`cameras[]` 含 `name/type/distance/fovy/follow{smoothing}` + `active`）；`set_follow(entity, smoothing)` 作用于活动相机，entity 由 C++ 运行时指定（P1-05 前 Lua 侧无稳定 entity id）；平滑为帧率无关指数平滑（见需求 `20261003-01`）。
- P1-05：`api.ecs` 最小接口面（P1 是否仅 `get_pos/set_pos/get_level/set_level`，是否含组件增删）。
